# 投影幕卡片顯示審核報告

日期：2026-07-10
範圍：`src/views/board/BoardProjectionView.tsx`（`CardStage` 元件）+ `src/constants/cards.ts`（`effectLines` 資料源頭）
方法：實際讀取三副牌堆（happiness/opportunity/news，共 160 張卡）的原始 JSON 資料，比對程式碼實際渲染邏輯，找出真的會在畫面上出現的問題（而非臆測）。

前情提要：本輪之前已完成的優化（不重複列出）：
- 效果摘要條（ImpactSummaryBar）、敘事文字降級、狀態列、標籤化 effectLines、家庭歷程說明壓縮、分類行合併、幸福卡摘要重複修正、移動氣泡。

## 一、高優先：仍在發生的真實 Bug

### 1.1 `<br>` 字面文字外露（尚未修正）
**位置**：`normalizeCardCopy()`（`src/constants/cards.ts:490`）沒有處理 `<br>`。

**證據**：實際抓取 JSON 資料，`description` 欄位含 `<br>` 的卡片數：

| 牌堆 | 含 `<br>` 張數 | 是否會顯示在投影幕 |
|---|---|---|
| happiness | 16 | 14 張是「家庭重要歷程」卡，走專屬表格分支不會顯示描述，**安全**；但 **H004、H021 兩張一般幸福卡會直接顯示**，且含 `<br>` |
| opportunity | 14 | **全部都是一般卡，會直接顯示**，且含 `<br>` |
| news | 0 | 無影響 |

**實際會出現的畫面**（節錄 H004 description）：
```
我曾經遇過一個非常喜愛的事物（藝術品、音樂、美景等皆可），每次回想起這個事物，就覺得很快樂。<br>抽到卡片的玩家，跟大家分享一個美麗的經歷，就能獲得幸福值2點。
```
`<br>` 會原封不動印在螢幕上，這正是「敘述雜亂」的具體來源之一。

**修法**：`normalizeCardCopy()` 加一行 `.replaceAll('<br>', '\n')`，讓它變成真正的換行，而不是字面文字。影響至少 **16 張卡**（2 張幸福卡 + 14 張機運卡），且是一行程式碼就能修的低成本高回報項目。

### 1.2 機運卡效果摘要重複（幸福卡的問題還沒收斂乾淨）
**位置**：`buildOpportunityCardMetaFromSchema()`（`cards.ts:407`）

**根因**：上一輪已經修正幸福卡的「幸福 +N 摘要重複」問題（原因是 `effects.summary` 常常直接以「幸福 +」開頭，跟下面結構化欄位的 push 撞在一起）。但同一類問題**在機運卡也存在，還沒修**：機運卡的 `effects.summary` 有些直接以「現金 -」開頭，會被 `parseImpactLines` 的前綴比對誤判成獨立的一筆現金支出，跟後面 `card.cashLoss` 的結構化 push 撞成兩個一模一樣的紅色「現金支出」色塊。

**證據**：實際確認到至少 7 張機運卡受影響（C035、C036、C037、C044、C049、C050、C052），內容例如：
```
C044 effects.summary = "現金 -8,000"
```
同時 `card.cashLoss` 也會 push 一次「現金 -8,000」——ImpactSummaryBar 會出現兩個一樣的「現金支出 8,000」色塊。

**修法**：跟幸福卡的修法邏輯一致——確認機運卡的 `effects.summary` 在「無 * 規則段落」時，內容是否已經完全被下面的結構化欄位涵蓋。從抓到的樣本看，這類「現金 -N」開頭的機運卡摘要，資訊確實跟 `cashLoss`/`cashGain` 等結構化欄位完全重疊，可以直接跳過 push（比照幸福卡的處理方式）。

### 1.3 股票卡表格化判斷條件脆弱，已有 1 張卡實際壞掉
**位置**：`CardStage` 內 `isStockCard` 判斷（`BoardProjectionView.tsx:442`）
```ts
const isStockCard = card.deck === 'news' && normalizedEffectLines.length === 8 && normalizedEffectLines.some(line => line.includes('A10'));
```

**根因**：股價卡固定會 push 8 檔股票的「代碼：價格」，但如果卡片還有 `specialRule`（例如「所有持股數減半」），會多 push 一行，導致 `effectLines.length` 變成 9，不再等於 8，`isStockCard` 判斷失敗。

**證據**：目前 26 張股價卡中，**N002 已經確定會壞掉**（它的 `specialRule` = 「所有持股數減半，不足1張捨去」）。壞掉後 N002 不會用漂亮的 A/B 區兩欄股票表格呈現，而是退化成 8 個「A10：150000」風格的普通標籤格子，且 `specialRule` 那句規則說明會被塞進規則框。

**修法**：判斷條件不要用「長度剛好等於 8」這種脆弱寫法，改成看是否存在對應到 `STOCK_SYMBOL_COLUMNS` 裡至少 4~8 個股票代碼的「代碼：數字」格式行（例如檢查 `remainingEffectLines.filter(l => STOCK_SYMBOL_COLUMNS.flat().some(sym => l.startsWith(sym + '：'))).length >= 6`），這樣即使多一行 `specialRule` 也不影響判斷，且 `specialRule` 那行會自然落到規則框裡正確顯示。

## 二、中優先：一致性與資訊架構問題

### 2.1 「自用幸福」跟其他幸福增減視覺權重不一致
**位置**：`IMPACT_LINE_MATCHERS`（`BoardProjectionView.tsx:290`）+ 房地產卡 `canSelfUse` 分支（`cards.ts` news builder）

房地產卡的自用幸福是 push 成「自用幸福：+2」，這個字串**不會**被 `幸福 +`/`幸福 -` 前綴比對到（因為它開頭是「自用幸福」不是「幸福」），結果它不會進效果摘要條的粉色大色塊，而是跟「總價」「頭期款」這種普通數字擠在同一個小格子裡。同樣是「幸福點增加」，玩起來語意一樣重要，畫面上呈現的視覺份量卻不一樣。

**修法**：在 `IMPACT_LINE_MATCHERS` 加一條 `{ prefix: '自用幸福 +', label: '幸福', tone: 'happiness' }`（連帶要把資料源頭那行的分隔符從「：」改成「 +」跟其他幸福格式一致，或是額外加一條專門吃「自用幸福：」開頭的 matcher）。

### 2.2 「需要分享故事／口頭分享」這類操作提醒被稀釋掉了
**位置**：上一輪的第③項優化（無冒號句子併入規則框）

`需要玩家分享故事`（幸福卡）、`需要完成口頭分享`（機運卡）這類文字，原本是給執行師/GM看的「操作提醒」——代表流程上需要主持人開口請玩家分享。上一輪把它們跟一般敘述句一起塞進規則框後，重要性被稀釋，混在一段話裡不容易一眼看到。

**建議**：這類「需要主持人介入」的提醒，比照狀態列的做法，獨立做成一個小的醒目標籤（例如規則框上方一個黃色小徽章「🗣 需要口頭分享」），而不是併入大段規則文字。

### 2.3 家庭歷程卡的 effectLines 是死資料
**位置**：`buildHappinessCardMetaFromSchema()` 裡 `familyMilestoneStatus.stageLines`／`目前進度：第 N 階段` 這兩行 push（`cards.ts:374-377`）

這兩行資料會被算出來、放進 `effectLines`，但 `CardStage` 的 `isFamilyMilestoneCard` 分支完全不會讀 `effectLines`（它直接讀 `card.familyMilestoneStatus.stages` 畫專屬表格）。這是純粹浪費運算、不影響畫面的低優先清理項目，可做可不做。

## 三、低優先／觀察項目（目前不需要動）

- **卡片標題長度**：三副牌堆最長標題 18 字（機運卡），目前 `clamp(2rem,7vw,3rem)` + `break-words` 綽綽有餘，不需處理。

## 五、追加調查（2026-07-10 後續）：股票卡片下方被裁切

使用者回報「股票卡片沒有完全顯示在頁面上，下方被遮住了」。以下是純程式碼追蹤分析（未改動任何程式碼）。

### 5.1 根本原因：新聞卡的 `effects.summary` 從未被清掉，股票卡多長出一整塊空白 UI

`buildNewsCardMetaFromSchema()`（`src/constants/cards.ts`）目前邏輯：
```ts
if (!hasDescriptionRuleSection(rawCard)) {
  pushUniqueLine(effectLines, rawEffectsSummary(rawCard));
}
```
幸福卡（本輪已修）、機運卡（上次請 Codex 修）都已經處理過「`effects.summary` 跟結構化欄位重複」的問題，**唯獨新聞卡（news）這個 builder 完全沒動過**。

實際抓資料確認：**所有 26 張股價卡（`stock_price`）的 `effects.summary` 都是同一句「更新股票價格」**，且沒有 `*` 規則段落，所以每次都會被 push 進 `effectLines`。

這行文字進到畫面上的路徑是：
1. `parseImpactLines()` 抓不到「更新股票價格」（不符合任何現金/幸福/月支出前綴），所以進 `rest`（也就是 `remainingEffectLines`）。
2. `parseLabelValueLines()` 因為它沒有冒號，判定為整句敘述（`label: null`）。
3. 因此它進了 `combinedRuleText`，在 `CardStage` 裡渲染成一個**獨立的米色規則框**（`px-4 py-4` 的區塊），位置就在股票兩欄表格的**正上方**。

也就是說，**每一張股票卡片，畫面上都會先出現一個完全沒有資訊價值的「更新股票價格」文字框，把下面 8 檔股票的兩欄表格往下推**。這個規則框本身的高度（padding + 行高 + margin）粗估落在 70~90px，在卡片總高度有限（`h-[min(78vh,760px)]`，實際可視高度會隨螢幕/視窗大小縮水）的情況下，很可能就是把股票表格擠出可視範圍、導致「下方被遮住」的直接原因。

### 5.2 同一根因、影響更大的卡：房市新訊（26 張，新聞卡裡最大宗）

檢查發現房市新訊（`real_estate`）的 `effects.summary` **完整重述了下面全部 6 個結構化欄位**，例如：
```
N029 summary: "總價 1,100,000；頭期款 100,000；貸款 1,000,000；月付款 5,000；租金 6,500；淨收益 +1,500"
```
這句話會跟緊接在後面單獨 push 的「總價：」「頭期款：」「貸款：」「貸款利息（月）：」「租金收入（月）：」「淨收益（月）：」六行完全重複，且因為是一整句話（無冒號），會整句塞進規則框——比股票卡的狀況更嚴重，房市新訊卡片被裁切的機率應該比股票卡更高。使用者這次回報的是股票卡，但房市新訊卡建議一併排查。

### 5.3 次要疑慮：捲軸隱藏後，溢出內容變成「無聲消失」

上一輪把卡片內容區加了 `no-scrollbar`（隱藏原生捲軸、保留可捲動性）。但投影幕是「給觀眾看」的被動螢幕，實際上不會有人去觸碰/拖曳捲動——所以理論上「可以捲動」在這個場景下等於「不可觸及」。這代表：只要卡片內容真的比可視高度長，不管有沒有隱藏捲軸，內容都會被裁掉（差別只在於「有沒有一條捲軸提示你還有更多內容」）。這也解釋了為什麼問題現在才被注意到——捲軸被隱藏後，裁切變得更難察覺。

### 5.4 建議修正計劃

| 順序 | 項目 | 修法 | 影響範圍 |
|---|---|---|---|
| 1 | 新聞卡 `effects.summary` 重複／無資訊價值 | 比照幸福卡/機運卡的做法，在 `buildNewsCardMetaFromSchema()` 移除或有條件跳過 `rawEffectsSummary` 的 push——至少「股價卡的『更新股票價格』」這句應該直接拿掉（0 資訊價值），房市新訊的完整重複摘要也建議一併拿掉 | 26 張股價卡 + 26 張房市新訊卡（共 52 張，佔新聞卡 58 張的九成） |
| 2 | 驗證卡片實際渲染高度 | 修完第 1 項後，建議實際開一場遊戲、抽到股價卡和房市新訊卡各一張，用瀏覽器量測卡片內容區實際高度 vs. 可視高度，確認是否還會溢出；如果修完第 1 項後仍會溢出，代表 8 列股票表格本身在小螢幕/小視窗下就是太高，需要進一步縮小行高或改成更緊湊的呈現 | 全部股價卡/房市新訊卡 |
| 3（保守備案） | 捲軸從隱藏改回「淡化顯示」 | 如果第 1、2 項做完仍有極少數卡片內容過長，考慮把 `no-scrollbar` 改回顯示一條細窄、低對比的捲軸（而非完全隱藏），讓執行師至少能看到「這張卡內容比較長」的視覺提示，即使畫面上沒人會真的去捲動它 | 全體卡片（保險做法，非必要） |

第 1 項是本次追加調查裡影響最大、修法最明確的項目，且跟先前①②項優化是同一套邏輯，風險低。建議優先處理。

## 附錄：驗證方法

本報告所有「受影響張數」皆透過直接讀取 `src/data/cards/*.cards.json` 並用腳本比對前綴/正則得出，非憑印象猜測。若要重新驗證，可用類似指令：

```bash
python3 -c "
import json
data = json.load(open('src/data/cards/happiness.cards.json'))
for c in data:
    if '<br>' in (c.get('description') or ''):
        print(c['id'], c['category'])
"
```
