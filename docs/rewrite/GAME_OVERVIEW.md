# GAME OVERVIEW

## 1. Game Concept

### 遊戲名稱

- 專案現有資料同時出現《第二人生》與《第二人生》兩種名稱。
- 目前正式規格文件多以《第二人生》作為系統名稱；本文件先沿用使用者指定的《第二人生》作為新版規劃標題，並在文末保留命名衝突。

### 遊戲類型

- 多人回合制人生模擬桌遊
- 財務教育與人生決策模擬遊戲
- 棋盤移動 + 卡片事件 + 市場波動 + 幸福計分的混合型遊戲

### 遊戲核心概念

- 玩家不是只追求有錢，而是要在有限的遊戲時間內，同時處理工作、家庭、資產、貸款、保險、投資、夢想與幸福。
- 棋盤上的每一步都可能帶來人生事件、金融事件或市場事件，玩家必須在現金流、風險與幸福之間做取捨。
- 財務自由、人生夢想與幸福值達標都是重要里程碑，但都不會單獨結束遊戲；真正的勝負仍要等整場遊戲正式結束後才判定。

### 遊戲設計目的

- 用遊戲方式讓玩家理解現金流、資產、負債與長期決策的關係。
- 讓玩家體驗「人生成功不等於只有財富」，幸福、家庭與夢想同樣是核心目標。
- 透過共同事件與全員市場事件，讓玩家感受到個人決策與群體環境同時作用的人生節奏。

### 玩家體驗目標

- 感受到每回合都有具體且有後果的決策。
- 清楚體驗資產成長與現金壓力並存的節奏。
- 在追求幸福、事業、家庭與夢想時，面對真實取捨。
- 在多人同局中感受到競爭、共鳴、共同承擔與互相影響。

## 2. Player Roles

### 執行師

#### 角色定位

- 遊戲的控場者、時間管理者與房間管理者。

#### 主要責任

- 建立房間與設定場次
- 開始遊戲
- 控制整局遊戲時間
- 發布或監看市場狀態
- 監看玩家狀態與回合進度
- 處理現有系統中的請求審核流程
- 結束遊戲與進入結算

#### 權限特徵

- 執行師不屬於棋盤上的一般玩家，不參與玩家回合順序。
- 執行師負責房間層級操作，不直接代替玩家做人生或財務決策。

### 玩家

#### 角色定位

- 真正參與棋盤、卡片、財務與人生決策的主體。

#### 主要責任

- 進行初始選擇：職業、目標企業、人生夢想
- 在自己的回合擲骰、移動、處理事件
- 管理現金、收入、支出、資產、負債與保險
- 回應家庭歷程、投資、收購、股利等多人事件
- 累積幸福值並追求自身人生目標

#### 權限特徵

- 當前回合玩家持有回合主要操作權。
- 非當前回合玩家仍可能因共享事件或常駐金融功能而需要回應或操作，但不因此取得回合控制權。

## 3. Core Gameplay

### 玩家主要在做什麼

- 擲骰在 52 格棋盤上移動。
- 經過或停留特定格子，觸發銀行、學校、維修廠、醫院與卡片事件。
- 從幸福卡、機運卡、新聞卡中遭遇人生事件、機會事件與市場事件。
- 在有限現金與月現金流壓力下做出投資、借貸、保險與生活選擇。

### 財務決策

- 玩家持續管理現金與每月現金流。
- 決策範圍包含股票、定存、不動產、企業、貸款、還款、保險與汽車。
- 任何正式交易都必須通過財務檢核後才成立。

### 人生決策

- 玩家要決定是否接受幸福卡、機運卡、家庭歷程與夢想相關事件。
- 玩家會在職涯成長、家庭進展、生活消費與長期夢想之間分配資源。

### 玩家互動

- 家庭歷程允許其他玩家共同參與。
- 資產收購類卡片會讓所有符合條件的玩家決定是否出售。
- 股利、股息、通膨與投資類事件可能同時影響多位玩家。

### 市場變化

- 新聞卡會推動股票行情、房市機會、店面機會、企業投資機會與創業貸款機會。
- 市場不是背景裝飾，而是持續改變玩家決策與資產價值的核心系統。

## 4. Core Gameplay Loop

正式的單回合核心流程如下：

```text
Turn Start
  ->
Roll Dice
  ->
Movement
  ->
Pass Events
  ->
Landing Event
  ->
Card / Special Event
  ->
Player Decision
  ->
Effect Resolution
  ->
Follow-up Event
  ->
Event Queue Complete
  ->
End Turn
```

### Turn Start

- 指派當前回合玩家。
- 若玩家處於停回合狀態，該回合會轉為跳過回合處理，而不是正常擲骰移動。

### Roll Dice

- 沒有汽車時，玩家只能擲一顆骰。
- 擁有汽車後，玩家每回合都可自行選擇擲一顆或兩顆骰。
- 兩顆骰規則只用於棋盤移動，不影響醫院骰、考試骰、家庭歷程骰或其他事件骰。

### Movement

- 玩家依骰點前進。
- 棋盤採固定方向的環狀循環。

### Pass Events

- 經過銀行、學校、維修廠時，會依正式順序建立經過事件。
- 經過事件必須在回合中被正式處理，不能被跳過。

### Landing Event

- 停留於銀行、學校、醫院、維修廠或卡片格時，會建立停留事件。

### Card / Special Event

- 若停在卡片格，會抽取對應牌堆卡片。
- 若停在特殊格，則進入對應事件流程，例如銀行事件、學校事件、醫院事件或維修事件。

### Player Decision

- 玩家可能需要決定接受或不接受某張卡片、是否參加考試、是否購買資產、是否參與共同事件、是否出售資產、是否投資等。

### Effect Resolution

- 所有效果都必須先經過正式揭示，再進入正式結算。
- 涉及金額、資產、負債、收入、支出的結果，需先完成財務檢核或正式財務更新。

### Follow-up Event

- 某些卡片或事件不會在當下完全結束，而會產生後續事件。
- 後續事件仍屬於正式事件鏈的一部分，必須在回合結束前完成。

### Event Queue Complete

- 只有當本回合產生的必要事件、共享事件、後續事件與必要財務處理全部完成後，事件佇列才算真正清空。

### End Turn

- 事件佇列清空、必要財務處理完成後，回合才正式結束。
- 之後才會切換到下一位玩家。

## 5. Full Game Flow

完整一局遊戲的正式流程如下：

```text
登入
  ->
大廳
  ->
建立 / 加入房間
  ->
執行師開局
  ->
玩家初始化
  ->
遊戲進行
  ->
遊戲結束
  ->
結算
```

### 登入

- 使用者先進入系統並取得自己的房間與角色身份。

### 大廳

- 玩家或執行師進入大廳。
- 執行師可建立房間。
- 玩家可輸入房號加入現有房間。

### 建立 / 加入房間

- 執行師建立房間並決定場次設定。
- 玩家加入後，房間內會形成執行師與玩家成員名單。

### 執行師開局

- 執行師開始遊戲後，房間由等待狀態進入遊戲進行狀態。
- 棋盤模式初始化，玩家回合順序建立。

### 玩家初始化

- 每位玩家依序完成初始選擇：
  - 選擇職業
  - 選擇目標企業
  - 選擇人生夢想
- 初始現金、初始薪資、初始幸福項目與相關目標隨之建立。

### 遊戲進行

- 玩家輪流進行回合。
- 棋盤事件、卡片事件、市場事件、財務處理與多人互動持續發生。
- 執行師控制時間、監看局勢並在現有系統中承接審核與房間層級操作。

### 遊戲結束

- 當遊戲時間到達，或執行師正式結束房間時，遊戲進入結束流程。

### 結算

- 遊戲正式結束後，依最終幸福值排序產生排名。
- 財務自由、夢想完成與幸福值達標都會作為里程碑被保留，但不會取代最終幸福排名。

## 6. Board Gameplay

### 52 格棋盤

- 棋盤是固定的 52 格環狀路徑。
- 所有玩家的初始位置都在 Index 0。
- Index 0 同時是起點與學校格。

### 移動

- 玩家在自己的回合擲骰移動。
- 沒有汽車時用一顆骰。
- 有汽車時可選擇一顆或兩顆骰。

### 經過格

- 正式經過事件包含：
  - 銀行
  - 學校
  - 維修廠

### 停留格

- 正式停留事件包含：
  - 卡片格
  - 銀行
  - 學校
  - 醫院
  - 維修廠

### 學校

- 經過或停留學校都會建立學校事件。
- 玩家可選擇是否參加考試。
- 只要參加考試，不論成功或失敗，考試結束後都可以再抽一張幸福卡。

### 銀行

- 經過銀行或停留銀行都會觸發一次銀行事件。
- 銀行事件固定流程是：
  - 領取月結餘
  - 自動處理月結餘規則
  - 玩家可選擇是否使用銀行服務
  - 銀行事件結束
- 每次經過銀行後，玩家都會取得一段可持續到自己下一回合開始前的銀行服務窗口。

### 維修廠

- 玩家沒有汽車時，維修廠不觸發。
- 玩家有汽車時：
  - 經過維修廠：擲骰並支付保養費，金額 = 點數 × 2,000
  - 停留維修廠：擲骰並支付保養費，金額 = 點數 × 2,000，且停回合 1 次

### 醫院

- 停留醫院時建立醫院事件。
- 正式流程為第二次擲骰，支付醫療費 = 點數 × 1,000，之後停回合 1 次。

### 卡片格

- 卡片格會依格子類型抽取幸福卡、機運卡或新聞卡。
- 卡片不會在抽牌當下直接生效，而是必須經過正式揭示與結算。

## 7. Card Gameplay

### 卡片結構總覽

- 現有正式卡池共 160 張：
  - 幸福卡 46 張
  - 機運卡 56 張
  - 新聞卡 58 張

### 幸福卡

- 幸福卡主要處理人生幸福、回憶、消費、家庭歷程與個人生活選擇。
- 其中包含：
  - 幸福回憶卡
  - 幸福家庭的重要歷程
  - 消費型幸福卡

### 機運卡

- 機運卡主要帶來機會、風險、能力成長、資產收購、醫療車損房損與多人影響事件。

### 新聞卡

- 新聞卡主要驅動股票市場、房市、店面市場、企業投資與創業貸款機會。

### Self Event

- 大多數卡片只影響抽到卡片的玩家本人。
- 例如多數幸福卡、部分醫療／維修／保養／個人支出型卡片。

### Shared Event

- 部分卡片會影響多位玩家。
- 例如：
  - 家庭歷程共同參與
  - 房屋 / 店面 / 企業收購
  - 全體玩家通膨
  - 股利 / 股息
  - 大型企業投資
  - 創業貸款

### Follow-up Event

- Follow-up Event 是正式事件，不是例外流程。
- 它可能來自：
  - 考試後追加抽幸福卡
  - 機運卡或新聞卡要求後續抽牌
  - 創業貸款後等待未來銀行擲骰升級

### 卡片正式流程

- 所有正式卡片都遵循：
  - Draw
  - Reveal
  - Resolve
  - Complete
- 效果不得在 Reveal 前生效。

### 牌堆循環

- 三個牌堆皆採：
  - Active Deck
  - Used Deck
- 抽過的卡不會立刻回到牌堆。
- 必須等整個牌堆抽完後才重新洗牌再使用。

## 8. Financial Gameplay

### 現金

- 現金是玩家可立即使用的可動用資金。
- 正式交易完成後，玩家不得維持負現金。

### 收入

- 玩家收入至少包含：
  - Salary
  - Passive Income
  - Dynamic Income

### 支出

- 玩家支出至少包含：
  - Tax
  - Living Expense
  - Transportation
  - Education
  - Medical
  - Childcare
  - Insurance
  - Loan Interest
  - Rank Expense

### 月現金流

- Monthly Cashflow = Total Income - Total Expense
- 每次經過銀行時，玩家都要執行一次 Payday。

### 股票

- 股票是常駐可交易資產。
- 股票價格由市場事件與新聞卡驅動。

### 不動產

- 玩家可透過房市新聞、購買事件或相關交易入口取得不動產。
- 房屋可涉及自住、出租、房貸與房屋保險。

### 企業

- 玩家可取得企業或店面類資產，並透過升級或投資取得現金流。

### 定存

- 開立定存需要銀行服務窗口。
- 解約定存不需要等待銀行窗口。

### 貸款

- 借款與還款屬於常駐金融功能。
- 正式負債包含信用貸款、強制負債、車貸、企業貸款與房貸等類型。

### 保險

- 正式保險類型包含：
  - 醫療保險
  - 房屋保險
  - 汽車保險
- 購買保險需要銀行服務窗口。

### 汽車

- 汽車是正式資產。
- 玩家任何時間都可購買汽車，只要符合金額條件。
- 玩家同一時間只能持有一輛汽車。

### 財務檢核

- 所有正式交易都必須完成財務檢核後才成立。
- 包含但不限於：
  - 股票
  - 借款
  - 還款
  - 保險
  - 定存
  - 定存解約
  - 汽車
  - 房屋
  - 企業
  - 卡片事件
  - 棋盤事件
  - 幸福事件
  - 強制付款

## 9. Happiness / Life Gameplay

### 幸福值

- 幸福值是遊戲主要評分依據。
- 玩家要透過幸福事件、幸福卡、家庭歷程、夢想與人生選擇累積幸福值。

### 幸福事件

- 任何會正式改變幸福值的結果，都屬幸福事件。
- 幸福值達到 100 分代表正式幸福里程碑，但不代表遊戲直接結束。

### 家庭歷程

- 幸福家庭的重要歷程是正式多人事件。
- 歷程依固定階段順序推進：
  1. 第一次約會
  2. 求婚
  3. 婚禮
  4. 第一個孩子
  5. 第二個孩子
- 其他玩家可透過擲骰大於等於 4 共同參與。

### 職涯

- 每位玩家都會選擇一個職業，擁有起始薪資、初始職級與後續升等路徑。
- 玩家可透過學校、終身學習與其他正式流程推進職涯成長。

### 人生選擇

- 遊戲不是只有賺錢，而是持續要求玩家選擇：
  - 要不要消費換取幸福
  - 要不要投資換取長期現金流
  - 要不要背負貸款換取更大人生布局
  - 要不要投入家庭與夢想

### 人生夢想

- 每位玩家都有一個人生夢想。
- 夢想完成是重要里程碑，但不會直接結束遊戲。

## 10. Multiplayer Interaction

### 家庭歷程加入

- 家庭歷程允許其他符合資格玩家共同參與。
- 所有符合資格玩家都必須完成回覆後，事件才可真正結束。

### 資產收購

- 房屋、店面與企業收購事件不是只影響抽卡者。
- 所有持有符合條件資產的玩家，都應能決定是否出售。

### 股利 / 股息

- 持有符合條件股票的所有玩家都會受到股利或股息影響。

### 投資事件

- 大型企業投資事件允許多位玩家共同參與，各自輸入投資金額並獨立完成財務處理。

### 創業貸款

- 創業貸款事件允許所有玩家自行選擇接受或拒絕。
- 接受者會建立後續與銀行相關的升級流程。

### 全員回覆機制

- 某些共享事件不是單一玩家決定後就結束。
- 這類事件必須等待所有符合資格玩家回覆完成，才能正式關閉。

## 11. Coach Gameplay

### 建立房間

- 執行師建立房間並產生房號。

### 開始遊戲

- 執行師將房間從等待狀態切換為進行狀態，正式開局。

### 時間控制

- 執行師控制整局遊戲計時、暫停與最終結束點。

### 市場發布

- 現有專案資料顯示，執行師可進行市場發布或更新，用於一般模式或控場用途。

### 玩家監控

- 執行師負責監看玩家的遊戲進度、回合順序、共享事件與結算狀態。

### 請求審核

- 現有專案仍保留部分由玩家送出、執行師審核的請求型流程。
- 這反映執行師除了控場，也承擔部分正式流程的核准責任。

### 結束遊戲

- 執行師可正式結束房間，帶入遊戲結算與排名。

## 12. Game Completion

### 遊戲如何結束

- 遊戲正式結束方式有兩種：
  - 到達預設遊戲時間
  - 執行師正式結束房間

### 幸福條件

- 幸福值達到 100 分是重要里程碑，但不是遊戲結束條件。

### 財務條件

- 財務自由屬於重要里程碑，但不是遊戲自動結束條件。

### 計分

- 遊戲正式結束時，每位玩家的最終評分等於其當時的正式幸福值。

### 結算

- 遊戲結束後依幸福值高低排序。
- 幸福值最高者獲勝。

## 13. Core Design Principles

### 幸福高於單純財富

- 遊戲的主要勝負指標是幸福值，不是資產總額或現金總額。

### 事件必須完整結束

- 所有正式事件、共享事件、後續事件與必要財務處理完成後，回合才可切換。

### Reveal 先於 Resolve

- 卡片與市場效果不得在揭示前生效。

### 棋盤是人生節奏，不是單純走格

- 每次移動都可能引發教育、醫療、家庭、金融與市場後果。

### 財務是遊戲骨架

- 所有正式交易都必須經過財務檢核。
- 現金、收入、支出、月現金流、資產與負債是玩家長期決策的核心約束。

### 共享事件必須等待所有人

- 多人共同參與不是裝飾，而是正式遊戲機制。

### 夢想、家庭、職涯與市場同等重要

- 玩家不是在玩單一路徑，而是在多條人生軸線上同步取捨。

## Conflict / Open Questions

### 1. 正式名稱衝突

- 現有專案名稱、Repo 名稱與部分素材使用《第二人生》。
- 正式 GDD / Product Specification 多使用《第二人生》。
- 新版專案需要先決定最終正式名稱。

### 2. 遊戲結束條件在 Legacy 實作與正式規格之間有衝突

- 正式規格明確指出幸福值達到 100、財務自由或人生夢想完成都不會直接結束遊戲。
- 但現有 Legacy 文件與部分歷史流程仍出現 `happiness >= 100` 被標記為 `isWin` 的痕跡。
- 新版需要明確只承認哪一套結束與勝利邏輯。

### 3. 執行師審核流程的正式地位仍有舊新並存現象

- Product Specification / GDD 已把回合、事件、銀行與財務規則正式化。
- Legacy 流程中仍保留多種玩家送出請求、執行師審核後才生效的舊式請求管線。
- 新版需要明確區分：哪些是正式遊戲規則，哪些只是 Legacy 操作流程。

### 4. 市場價格權威在 Legacy 中出現副本分裂

- 正式規格已將共享市場價格視為正式來源。
- Legacy 盤點仍記錄 `room.marketPrices` 與玩家本地副本並存。
- 新版在「玩家如何玩」層面應只有一份正式行情來源。

### 5. 資產命名仍存在舊資料殘留

- 正式規格已統一使用「汽車」。
- 既有型別與舊資料中仍可見 `飛行器` 等 Legacy 名稱。
- 新版需要統一最終玩家可見的正式詞彙。

### 6. 故事分享與主持人確認的正式責任邊界需再收斂

- 幸福回憶卡資料庫已寫明需要故事分享與執行端 / 主持人確認後才發放幸福值。
- 但這套確認機制目前主要存在於卡片資料與 Legacy 流程說明，不是 Product Specification 的高階通則。
- 新版若要保留此體驗，需要在新版規格中明確界定其正式地位。
