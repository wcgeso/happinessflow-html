## Purpose

本文件定義《第二人生》的正式貸款系統。

本文件只負責信用貸款、房貸、車貸、企業貸款、強制負債、自動償還與貸款狀態的正式設計。

本文件不得重新定義產品規則。

所有正式貸款規則只能引用 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認 Decision。

## Scope

### 本文件負責

- 定義正式貸款類型
- 定義貸款與資產的正式附掛關係
- 定義借款、還款與清償規則
- 定義強制負債的正式生成與自動償還規則
- 定義貸款狀態與狀態轉換
- 定義貸款系統與其他系統的依賴關係

### 本文件不負責

- 重新定義銀行事件與銀行服務窗口流程
- 重新定義正式財務檢核流程
- 重新定義資產購買、出售與估值規則
- 重新定義月結算與收入支出規則
- 重新定義棋盤、卡片或事件流程
- 重新定義房屋或企業本體規則

### 邊界原則

- 貸款系統只定義貸款負債本體與其清償語意。
- 借款與還款的成立條件由 `FINANCIAL_SYSTEM.md` 承接。
- 銀行服務窗口的權限邊界由 `BANK_SYSTEM.md` 承接。
- 資產附掛關係由 `ASSET_SYSTEM.md` 承接。
- 本文件不得反向重寫其他系統已明確擁有的責任。

## State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待成立 | 表示貸款申請或負債來源已存在，但尚未正式成立 | 玩家提出借款，或正式規則要求建立強制負債，但尚未完成正式檢核 | 通過正式檢核並寫入後離開 | 進行正式檢核、建立正式貸款資料 | 視為已成立、進行還款 |
| 已成立 | 表示貸款已正式成立，且仍有未清償餘額 | 正式檢核通過且交易成立 | 進入還款中或已清償時離開 | 持續存在、等待還款、承接資產附掛關係 | 略過還款直接清除負債 |
| 還款中 | 表示貸款正在進行正式還款處理 | 玩家主動還款，或正式扣款流程開始處理一般貸款 | 還款完成後，依餘額回到已成立或進入已清償 | 減少本金、記錄正式交易、更新負債餘額 | 讓未完成的還款視為已清償 |
| 自動償還中 | 表示強制負債正在進行正式自動償還 | 系統產生可償還現金且存在強制負債 | 自動償還完成後，依餘額回到已成立或進入已清償 | 優先扣減強制負債、更新正式交易紀錄 | 將一般貸款納入自動償還 |
| 已清償 | 表示該筆貸款已無未清償餘額 | 剩餘本金歸零且正式清償完成 | 重新建立新貸款時離開 | 保留正式交易紀錄 | 再次對同一筆貸款執行還款 |

## Rules

### 貸款類型規則

- 正式貸款類型只包含以下五種：
  - 信用貸款
  - 房貸
  - 車貸
  - 企業貸款
  - 強制負債
- 信用貸款不附掛特定資產。
- 房貸、車貸、企業貸款都屬於附掛貸款，必須與對應資產建立正式關聯。
- 強制負債不是玩家主動選擇的借款類型，只能因支付不足而形成。

### 成立規則

- 所有正式貸款都必須先通過財務檢核，才可正式成立。
- 借款與還款屬於常駐金融功能，不受銀行服務窗口限制。
- 正式貸款成立後，必須寫入正式交易紀錄。
- 若正式貸款與資產存在附掛關係，該關係必須在成立時一併建立。

### 附掛規則

- 房貸、車貸、企業貸款都必須對應到唯一的正式資產關聯。
- 信用貸款與強制負債不得建立資產附掛。
- 附掛貸款的正式歸屬，以對應資產與負債資料的正式關聯為準。
- 資產出售時，若存在附掛貸款，該筆貸款必須一併依正式流程處理其結算關係。

### 還款規則

- 一般貸款不得自動清償，只能依玩家主動還款或正式扣款規則處理。
- 還款時必須先完成正式財務檢核，再更新剩餘本金與交易紀錄。
- 還款不得讓現金維持負數。
- 若還款不足，必須先完成正式補足處理後，才可讓還款正式成立。

### 自動償還規則

- 只有強制負債可以進入自動償還流程。
- 自動償還的優先順序必須高於其他任何正式貸款。
- 自動償還只處理強制負債，不得順帶清償信用貸款、房貸、車貸或企業貸款。
- 當系統產生可償還現金時，若存在強制負債，必須先處理強制負債。

### 負債併存規則

- 同一玩家可以同時持有多筆正式貸款。
- 若存在強制負債，強制負債必須優先於其他貸款被處理。
- 正式貸款的清償順序，除強制負債外，依玩家主動操作與正式交易流程決定。
- 同一資產若已存在附掛貸款，不能在未處理原關聯前再次建立新的附掛貸款關係。

### 遊戲結束規則

- 遊戲正式結束後，不得再建立新的貸款。
- 遊戲正式結束後，不得再執行新的還款。
- 遊戲正式結束後，不得再執行新的自動償還。

## State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待成立 | 進入已成立 | 正式財務檢核通過且交易成立 | 待成立 -> 已成立 | 待成立 -> 還款中、待成立 -> 已清償 |
| 待成立 | 進入自動償還中 | 正式規則要求建立強制負債且可開始處理 | 待成立 -> 自動償還中 | 待成立 -> 已成立 |
| 已成立 | 進入還款中 | 玩家主動還款或正式扣款流程開始 | 已成立 -> 還款中 | 已成立 -> 待成立 |
| 已成立 | 進入自動償還中 | 系統產生可償還現金且存在強制負債 | 已成立 -> 自動償還中 | 已成立 -> 還款中（一般貸款不得自動轉入） |
| 還款中 | 回到已成立 | 部分還款完成且仍有剩餘本金 | 還款中 -> 已成立 | 還款中 -> 待成立 |
| 還款中 | 進入已清償 | 最後一筆本金已清償 | 還款中 -> 已清償 | 還款中 -> 自動償還中 |
| 自動償還中 | 回到已成立 | 自動償還後仍有剩餘本金 | 自動償還中 -> 已成立 | 自動償還中 -> 還款中 |
| 自動償還中 | 進入已清償 | 強制負債已完全清償 | 自動償還中 -> 已清償 | 自動償還中 -> 待成立 |
| 已清償 | 重新建立 | 新一筆正式貸款成立 | 已清償 -> 待成立 | 已清償 -> 還款中、已清償 -> 自動償還中 |

## Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 玩家在沒有銀行服務窗口時申請借款或還款 | 是否可成立 | 可以。借款與還款屬常駐金融功能，不受銀行服務窗口限制。 |
| 玩家試圖以強制負債作為主動借款選項 | 是否可視為正式貸款 | 不可以。強制負債只能因支付不足而形成。 |
| 同一資產已存在附掛貸款 | 是否可再次建立新的附掛貸款 | 不可以。必須先處理原有附掛關係，再建立新的正式關聯。 |
| 資產出售時仍有附掛貸款 | 所有權移除與負債處理是否可分離 | 不可以。出售流程必須同步處理對應貸款的正式結算關係。 |
| 系統產生可償還現金時同時存在強制負債與一般貸款 | 應先處理哪一筆 | 必須先處理強制負債；一般貸款不得進入自動償還。 |
| 玩家現金不足卻要還款 | 還款是否可直接成立 | 不可以。必須先完成正式補足處理，再重新通過財務檢核。 |
| 同一玩家同時持有多筆貸款 | 償還順序是否混亂 | 以強制負債為最高優先，其餘貸款依玩家主動操作與正式交易流程處理。 |
| 遊戲正式結束後仍有未清償貸款 | 是否可再還款或自動償還 | 不可以。遊戲正式結束後不得再建立或變動任何貸款狀態。 |

## Design Principles

- 單一職責：本文件只定義正式貸款、強制負債、還款與自動償還規則。
- 模組化：借款入口、財務成立與資產附掛關係分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔銀行事件、資產購買、棋盤入口或月結算主流程責任。
- 高內聚：所有貸款類型、附掛、清償與狀態轉換規則集中於本文件。
- 單一權威來源：正式負債規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴銀行、財務與資產系統，不得要求它們反向依賴本文件。
- 依賴方向固定：貸款系統承接上游財務與資產規則，並供下游房屋與企業系統引用。
- 資料與 UI 分離：本文件只描述正式貸款資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程或執行細節。
- 產品規則不得寫進程式：貸款規則調整必須先更新正式規格。

## Writing Rules
