## Purpose

本文件定義家庭系統的正式設計，負責說明家庭歷程、共同參與、等待機制、完成條件與 Family Event 的正式規則。

本文件的責任，是把已確認的產品規則轉化為可維護、可分工、可延伸的家庭系統設計。

本文件不得重新定義產品規則。

所有家庭相關的正式規則都必須以 Product Specification 與已確認的 Decision 為來源。

## Scope

### 本文件負責

- 定義家庭歷程的正式責任範圍
- 定義 Family Event 的正式邊界
- 定義共同參與的正式規則
- 定義等待機制的正式規則
- 定義完成條件與收束條件
- 定義家庭系統的正式資料模型與狀態機

### 本文件不負責

- 重新定義卡片抽取、揭示與結算流程
- 重新定義回合順序或回合切換規則
- 重新定義財務檢核、資產、負債或市場規則
- 重新定義幸福值計分與最終排名規則
- 描述任何介面、操作流程或程式實作

### 邊界原則

- 家庭系統只負責家庭歷程本體與其共同參與流程
- 家庭歷程必須承接卡片系統所建立的正式卡片事件，不得自行創造新的卡片生命週期
- 家庭歷程的等待與收束必須服從事件系統的正式完成條件
- 若家庭歷程的結果會影響幸福值，最終承接必須交由幸福系統處理

## Definitions

| 名詞 | 定義 |
|---|---|
| 家庭歷程 | 由家庭歷程卡觸發的正式多人歷程。其正式內容包含共同參與、等待回覆、收束與完成，不負責卡片抽取本身。 |
| Family Event | 家庭歷程在系統層的正式事件形態。其責任是維持共同參與、保存回覆、判定等待是否結束，並在條件成立後完成收束。 |
| 共同參與 | 符合資格的玩家必須各自完成正式回覆的規則。共同參與不是可選附加流程，而是家庭歷程的一部分。 |
| 符合資格玩家 | 依本次家庭歷程的正式條件，被納入回覆範圍的玩家。其名單必須明確且可追蹤。 |
| 回覆 | 符合資格玩家對本次家庭歷程所提交的正式結果。可用結果僅限參與成功、參與失敗、拒絕參與。 |
| 等待機制 | Family Event 在所有符合資格玩家回覆完成前，持續維持的正式等待狀態。等待機制的存在目的，是防止來源事件提早完成。 |
| 收束 | Family Event 已取得所有必要回覆，且所有與本次家庭歷程相關的正式結果都已處理完畢，準備完成的狀態。 |
| 完成條件 | Family Event 可以正式結束所必須同時滿足的條件集合。任何一項未成立，Family Event 都不得完成。 |
| 家庭結果 | 本次家庭歷程完成後所留下的正式結果摘要。若結果會導向其他系統效果，仍須由對應系統承接。 |

## State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待建立 | 表示家庭歷程尚未進入正式共同參與流程 | 來源家庭歷程卡已成立，但共同參與尚未開啟 | Family Event 正式建立後離開 | 建立符合資格玩家名單、建立回覆需求 | 直接宣告完成、直接套用結果 |
| 等待回覆 | 表示符合資格玩家仍在提交回覆 | Family Event 已建立，且仍有至少一位符合資格玩家未完成回覆 | 所有必要回覆完成後離開 | 接收正式回覆、維持等待機制 | 提前收束、提前結束來源事件 |
| 收束中 | 表示所有必要回覆已到齊，正在彙整正式結果 | 全部符合資格玩家已完成回覆，且相關結果開始收束 | 所有正式結果與後續承接完成後離開 | 彙整家庭結果、承接需要的後續效果 | 重新打開未完成回覆、跳過結果處理 |
| 已完成 | 表示 Family Event 已正式結束 | 完成條件全部成立，且收束完成 | 無 | 交還事件完成權、允許來源事件完成 | 再次要求回覆、再次變更同一家庭結果 |

## Rules

### 1. 家庭歷程規則

1. 家庭歷程屬於正式多人事件。
2. 家庭歷程只能由家庭歷程卡建立，不得由其他事件臨時替代。
3. 家庭歷程一旦成立，即形成獨立的 Family Event 收束要求。
4. 家庭歷程不得在符合資格玩家尚未完成回覆前自行結束。

### 2. Family Event 規則

1. Family Event 是家庭歷程在系統層的正式事件形態。
2. Family Event 的責任只包含共同參與、等待、收束與完成。
3. Family Event 不負責卡片抽取，也不負責重新定義卡片內容。
4. Family Event 完成前，來源卡片事件不得視為已完成。
5. Family Event 完成前，任何需要此事件成立的下游結果都不得視為最終成立。

### 3. 共同參與規則

1. 每位符合資格玩家都必須各自完成正式回覆。
2. 回覆結果只允許以下三種：
   - 參與成功
   - 參與失敗
   - 拒絕參與
3. 同一位符合資格玩家在同一個 Family Event 中只能保留一個正式回覆。
4. 重複回覆不得改寫已完成的正式回覆結果。
5. 共同參與只代表該玩家完成自己的回覆責任，不代表取得來源卡片的主責權。

### 4. 等待機制規則

1. Family Event 建立後，只要仍有符合資格玩家未完成回覆，就必須維持等待狀態。
2. 等待機制的目的，是確保來源事件不會在共同參與未完成前提早收束。
3. 等待機制期間，不得把 Family Event 視為已完成。
### 5. 完成條件規則

1. Family Event 的完成條件必須同時滿足以下項目：
   - 符合資格玩家名單已確立
   - 所有符合資格玩家都已完成正式回覆
   - 所有與回覆相關的正式結果都已收束
   - 任何會影響下游系統的正式承接都已完成
2. 只要任一條件未成立，Family Event 就不得完成。
3. Family Event 完成後，來源卡片事件才可進入最終完成。
4. Family Event 完成後，才能把本次家庭歷程視為正式收束。

### 6. 結果承接規則

1. 家庭歷程的正式結果只描述本次共同參與的完成結果。
2. 若家庭結果會影響幸福值，必須由幸福系統承接。
3. 本文件不得重新定義幸福值的計分方式或最終排名。
4. 若家庭結果導向其他正式效果，必須由對應下游系統承接，不得在本文件重複定義。

## Flow

```text
開始
  ->
來源家庭歷程卡成立
  ->
建立 Family Event
  ->
確立符合資格玩家
  ->
進入等待回覆
  ->
接收所有正式回覆
  ->
進入收束中
  ->
彙整正式結果
  ->
完成所有必要承接
  ->
Family Event 已完成
  ->
完成
```

## State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待建立 | 進入等待回覆 | Family Event 正式建立且存在符合資格玩家 | 待建立 -> 等待回覆 | 待建立 -> 已完成 |
| 待建立 | 進入收束中 | Family Event 正式建立，且已具備進入正式收束的條件 | 待建立 -> 收束中 | 待建立 -> 已完成 |
| 等待回覆 | 進入收束中 | 所有符合資格玩家都已完成正式回覆 | 等待回覆 -> 收束中 | 等待回覆 -> 已完成 |
| 收束中 | 進入已完成 | 所有正式結果與必要承接都已完成 | 收束中 -> 已完成 | 收束中 -> 等待回覆 |
| 已完成 | 無下一正式狀態 | Family Event 已正式結束 | 無 | 重新回到待建立或等待回覆 |

## Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 同一位玩家重複提交回覆 | 可能造成結果被覆寫 | 只承認第一筆正式回覆，重複回覆不得改變結果。 |
| 有玩家尚未回覆 | Family Event 是否可先完成 | 不可。所有符合資格玩家都完成回覆前，不得完成。 |
| 部分玩家已回覆成功，但仍有後續結果待承接 | 事件是否可視為完成 | 不可。仍須維持在收束中，直到必要承接完成。 |
| 來源卡片事件想先完成 | 是否可略過家庭等待 | 不可。Family Event 完成前，來源卡片事件不得完成。 |
| 回覆結果已成立，但家庭結果尚未彙整 | 是否可進入完成 | 不可。必須先進入收束中，完成正式結果彙整後才可完成。 |
| 家庭歷程完成後又出現新回覆要求 | 是否可追加到同一事件 | 不可。已完成的 Family Event 不得再追加新的正式回覆。 |
| 符合資格玩家身分在等待中產生變動 | 是否影響本次等待與完成條件 | 仍以本次 Family Event 已正式確立的資格範圍與完成條件為準。 |

## Design Principles

- 單一職責：本文件只定義家庭歷程、共同參與、等待機制、完成條件與家庭事件邊界。
- 模組化：卡片生命週期、事件完成模型與幸福承接皆以引用上游系統方式處理。
- 低耦合：本文件不承擔卡片抽牌、回合切換、財務成立或幸福計分主責。
- 高內聚：所有家庭歷程等待、回覆、收束與完成規則集中於本文件。
- 單一權威來源：家庭相關正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴事件、卡片與幸福系統，不得反向要求它們依賴本文件。
- 依賴方向固定：家庭系統承接上游事件與卡片結果，並把幸福變動交由上游幸福系統承接。
- 資料與 UI 分離：本文件只描述正式家庭資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程或同步細節。
- 產品規則不得寫進程式：家庭規則調整必須先更新正式規格。
