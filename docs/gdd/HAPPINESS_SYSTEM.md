# Purpose

本文件定義《第二人生》的正式幸福系統。

本文件只負責幸福值、幸福事件、幸福卡、幸福里程碑、最終評分與排名規則的正式設計。

本文件不得重新定義產品規則。

所有幸福相關的正式規則皆以上游產品規格與已確認決策為準；本文件只負責將其整理為可維護、可引用、可驗證的正式設計。

# Scope

## 本文件負責

- 定義幸福值的正式責任與變動來源
- 定義幸福事件的正式範圍與處理邊界
- 定義幸福卡在幸福系統中的正式語意
- 定義幸福里程碑的正式成立條件
- 定義最終評分的正式計算方式
- 定義遊戲結束後的排名規則

## 本文件不負責

- 重新定義卡片抽牌、揭示與結算流程
- 重新定義財務檢核、交易成立與月結算規則
- 重新定義人生夢想與家庭歷程的正式條件
- 重新定義回合、棋盤或銀行流程
- 描述任何程式、介面或技術實作

## 邊界原則

- 幸福值的來源與變動結果由本文件承接。
- 幸福卡的生命週期由 `CARD_SYSTEM.md` 定義，本文件只承接其幸福結果。
- 涉及金額、支付、收入、支出、資產或負債的幸福結果，必須先由 `FINANCIAL_SYSTEM.md` 完成正式財務成立。
- 幸福里程碑不等於遊戲結束。
- 最終評分與排名只在遊戲正式結束後才固定。

# Definitions

| 名詞 | 定義 |
|---|---|
| 幸福值 | 玩家目前持有的正式幸福分數，用於描述其人生幸福狀態，並作為最終評分的唯一基礎。 |
| 幸福事件 | 任何會正式改變玩家幸福值，或會正式判定幸福里程碑的事件、效果或結果。 |
| 幸福卡 | 以幸福值變動為主要正式效果的卡片事件；其抽牌、揭示與結算由 `CARD_SYSTEM.md` 承接。 |
| 幸福里程碑 | 玩家幸福值達到 100 分時所達成的正式里程碑。 |
| 最終評分 | 遊戲正式結束時，玩家依當時幸福值取得的正式評分結果。 |
| 排名 | 遊戲正式結束後，依最終評分排序得到的玩家名次結果。 |

# Data Model

| 欄位名稱 | 型別 | 用途 | 限制 | 說明 |
|---|---|---|---|---|
| playerHappiness | 整數 | 記錄玩家目前的正式幸福值 | 必須可被正式幸福事件與幸福卡變動 | 為最終評分的唯一基礎 |
| happinessLedger | 紀錄列表 | 記錄每次幸福值變動的正式來源與數值 | 每筆紀錄都必須可追溯來源 | 用於驗證幸福值變化是否符合正式規則 |
| happinessMilestoneReached | 布林值 | 記錄玩家是否已達成幸福里程碑 | 一旦達成即維持為真 | 只代表里程碑狀態，不代表遊戲結束 |
| happinessMilestoneValue | 整數 | 定義幸福里程碑門檻 | 固定為 100 | 依正式產品規格不得任意變動 |
| finalScore | 整數或空值 | 記錄遊戲正式結束時的最終評分 | 遊戲未結束前應為空值 | 必須等到遊戲結束後才可固定 |
| finalRank | 名次或空值 | 記錄遊戲正式結束後的名次 | 排名未完成前應為空值 | 由最終評分排序得出 |

# State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 穩定 | 表示目前沒有正在處理的幸福變動 | 前一筆幸福事件已完成，且未進入結算封存 | 有新的正式幸福事件或幸福卡結果需要處理時離開 | 讀取目前幸福值、等待新幸福結果 | 直接改寫最終評分、直接產生排名 |
| 幸福變動中 | 表示正在套用正式幸福結果 | 有正式幸福事件、幸福卡結果或其他正式來源需要更新幸福值 | 幸福值與來源紀錄完成後離開 | 套用幸福增減、寫入幸福紀錄、檢查里程碑 | 跳過正式來源、略過來源紀錄 |
| 結算封存 | 表示遊戲已正式結束，幸福結果已鎖定 | 遊戲正式結束且最終評分已計算 | 無 | 讀取最終評分與排名 | 再次變更幸福值、重新計算排名 |

# Rules

## 幸福值規則

1. 幸福值必須以整數形式記錄。
2. 幸福值只可由正式幸福事件、幸福卡結果，或其他正式規則明確指定的幸福來源變動。
3. 每一次幸福值變動都必須能對應到正式來源。
4. 幸福值的變動結果必須寫入幸福紀錄。
5. 幸福值的最終權威來源是玩家目前的正式幸福值，而不是卡片顯示、暫存結果或其他非正式副本。

## 幸福事件規則

1. 幸福事件是所有會正式改變幸福值，或會正式判定幸福里程碑的事件總稱。
2. 幸福事件若包含金額、支付、收入、支出、資產或負債效果，必須先由 `FINANCIAL_SYSTEM.md` 完成正式成立。
3. 幸福事件的結果一旦成立，就必須同步反映到幸福值與幸福紀錄。
4. 幸福事件不得在正式來源尚未成立前先行生效。
5. 幸福事件完成前，對應的幸福值變動不得視為最終結果。

## 幸福卡規則

1. 幸福卡屬於正式卡片事件，其抽牌、揭示、結算與完成由 `CARD_SYSTEM.md` 承接。
2. 幸福卡的正式責任，是提供會影響幸福值的結果。
3. 幸福卡在正式結算完成前，不得直接改寫幸福值。
4. 幸福卡若同時包含其他系統的正式效果，應先由對應系統完成其正式成立條件，再回到幸福結果承接。
5. 幸福卡的結果完成後，必須寫入幸福紀錄。

## 幸福里程碑規則

1. 當玩家幸福值達到 100 分時，該玩家正式達成幸福里程碑。
2. 幸福里程碑只代表人生里程碑，不代表遊戲結束。
3. 幸福里程碑達成後，玩家仍須繼續進行遊戲，直到正式結束條件成立。
4. 幸福里程碑一旦達成，即視為該里程碑正式完成，不因後續幸福值變動而失效。
5. 幸福里程碑的成立狀態必須可追溯。

## 最終評分規則

1. 遊戲正式結束時，每位玩家的最終評分等於其當時的正式幸福值。
2. 最終評分不採用額外加權公式。
3. 最終評分只在遊戲正式結束後固定。
4. 遊戲正式結束後，不得再因任何後續事件改寫最終評分。

## 排名規則

1. 遊戲正式結束後，依最終評分由高到低排序。
2. 最終評分較高者排名在前。
3. 排名一旦完成，即視為正式封存結果。

## 交界規則

1. 幸福卡的卡片流程由 `CARD_SYSTEM.md` 負責，本文件只承接幸福結果。
2. 涉及金額或負債的幸福結果由 `FINANCIAL_SYSTEM.md` 負責正式成立。
3. 人生夢想與家庭歷程若會影響幸福值，應由其各自系統完成正式結果後，再交由本文件承接幸福值變動。
4. 本文件不得重新定義夢想、家庭或財務的正式成立條件。

# Flow

```text
開始
  ->
正式幸福事件或幸福卡結果成立
  ->
進入幸福變動中
  ->
套用幸福值變動
  ->
寫入幸福紀錄
  ->
檢查是否達成幸福里程碑
  ->
回到穩定
  ->
若遊戲正式結束
  ->
計算最終評分
  ->
產生排名
  ->
進入結算封存
  ->
完成
```

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 穩定 | 進入幸福變動中 | 有正式幸福事件、幸福卡結果或其他正式來源需要處理 | 穩定 -> 幸福變動中 | 穩定 -> 結算封存 |
| 幸福變動中 | 回到穩定 | 幸福值變動與幸福紀錄已完成，且遊戲尚未結束 | 幸福變動中 -> 穩定 | 幸福變動中 -> 結算封存 |
| 穩定 | 進入結算封存 | 遊戲正式結束且最終評分已計算完成 | 穩定 -> 結算封存 | 穩定 -> 幸福變動中（若遊戲已正式結束） |
| 幸福變動中 | 進入結算封存 | 遊戲正式結束且當前幸福結果已完成 | 幸福變動中 -> 結算封存 | 幸福變動中 -> 穩定後再進入另一筆幸福變動 |
| 結算封存 | 封存完成 | 最終評分與排名已固定 | 無 | 任何回到穩定或幸福變動中的轉換 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 同一回合內出現多個幸福效果 | 幸福值更新順序可能混亂 | 必須依正式事件順序逐一處理，且每一筆都要有來源紀錄。 |
| 幸福值達到 100 後又再變動 | 里程碑是否失效 | 不會失效。幸福里程碑一旦達成，即維持成立。 |
| 幸福卡同時涉及金額與幸福值 | 可能先套用未成立結果 | 必須先完成財務成立，再套用幸福結果。 |
| 遊戲正式結束前已達成里程碑 | 是否可提前產生最終評分 | 不可以。最終評分只在遊戲正式結束時計算。 |
| 遊戲正式結束後仍有其他正式結果想改變幸福值 | 是否允許回寫 | 不允許。結算封存後不得再改變幸福值、最終評分或排名。 |
| 幸福來源無法追溯 | 是否可視為正式結果 | 不可。無法追溯來源的幸福變動不得視為正式成立。 |

# Design Principles

- 單一職責：本文件只定義幸福值、幸福事件、幸福里程碑、最終評分與排名邊界。
- 模組化：卡片生命週期、財務成立、夢想與家庭承接皆以引用上游或下游 GDD 方式處理。
- 低耦合：本文件不在內部重複定義卡片、財務、夢想或家庭系統的正式流程。
- 高內聚：所有幸福值來源、幸福結果與最終評分規則集中於本文件。
- 單一權威來源：幸福相關正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件不得反向依賴其下游的夢想與家庭系統。
- 依賴方向固定：幸福系統只承接上游卡片與財務結果，並供下游系統引用。
- 資料與 UI 分離：本文件只描述正式幸福資料與規則，不描述任何呈現方式。
- 規則與實作分離：本文件只定義正式規則，不描述技術實作。
- 產品規則不得寫進程式：任何幸福規則調整都必須先更新正式規格。

# Writing Rules

- 不得重新定義 Product Specification 已確認的幸福規則。
- 不得把未確認的同分排名方式寫成正式規則。
- 不得包含現況分析、選項比較、建議段落、待辦項目或 RFC 分析內容。
- 不得描述程式、框架、介面協定、資料庫或畫面細節。
- 若幸福效果涉及其他系統，必須以引用方式承接，不得在本文件複製他系統規則。

# Modular Design Rules

- 本文件只負責幸福系統，不承擔卡片、財務、夢想、家庭或回合系統責任。
- 本文件可依賴 `docs/gdd/CARD_SYSTEM.md` 與 `docs/gdd/FINANCIAL_SYSTEM.md`，不得反向要求它們依賴本文件。
- 下游系統若需要幸福值、里程碑或最終評分規則，必須引用本文件，不得重新定義。
- 本文件與其他 GDD 的依賴方向必須維持 DAG，不得形成循環依賴。
- 幸福規則只在本文件定義一次，其他文件若需要使用，應以引用方式承接。
