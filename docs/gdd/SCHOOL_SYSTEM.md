# Purpose

本文件定義學校系統的正式設計。

本文件只負責學校事件、考試、升等承接、考後幸福卡、學校事件流程與學校狀態機的正式規則與正式資料模型。

本文件不得重新定義產品規則。

所有學校相關正式規則皆以上游產品規格、已確認 Decision、Core GDD 與既有第一批 Domain GDD 為正式來源。本文件只承接學校事件本體與其正式結果，不重寫上游規格。

# Scope

## 本文件負責

- 定義學校系統的正式責任範圍
- 定義學校事件的正式入口與完成邊界
- 定義考試參與、考試結果與考後幸福卡的正式流程
- 定義學校事件與職業升等結果之間的正式承接邊界
- 定義學校系統的正式 State 與狀態轉換

## 本文件不負責

- 重新定義回合順序或回合切換規則
- 重新定義棋盤移動、經過與停留判定規則
- 重新定義卡片抽取、揭示與結算流程
- 重新定義職業本體、薪資、職級或終身學習規則
- 描述任何程式、畫面或技術實作

## 邊界原則

- 學校系統只負責學校事件本體、考試流程、是否抽取考後幸福卡，以及學校事件的收束條件。
- 學校事件入口由 `BOARD_SYSTEM.md` 承接，事件生命週期由 `EVENT_SYSTEM.md` 承接，考後幸福卡生命週期由 `CARD_SYSTEM.md` 承接。
- 升等屬職業規則，不等同於學校考試；學校系統只負責產生可供 `PROFESSION_SYSTEM.md` 下游承接的正式考試結果。
- 本文件不定義終身學習流程；終身學習的正式邊界以 `PROFESSION_SYSTEM.md` 為準。

# Definitions

| 名詞 | 定義 |
|---|---|
| 學校事件 | 玩家經過或停留學校格時觸發的正式事件。其內容包含是否參加考試、考試結果與考後幸福卡承接。 |
| 考試 | 學校事件中的正式選擇流程。玩家可決定是否參加。 |
| 應試玩家 | 對本次學校事件具有主要承接責任的玩家。 |
| 考試結果 | 本次考試完成後所留下的正式結果，可為成功、失敗或未參加。 |
| 升等承接 | 當考試結果需要影響職業成長時，由職業系統承接其正式結果的規則。 |
| 考後幸福卡 | 玩家選擇參加考試後，不論成功或失敗，都必須承接的一張正式幸福卡事件。 |
| 學校完成 | 學校事件、考試結果與必要的考後幸福卡皆已正式處理完畢的狀態。 |

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |

| 待觸發 | 表示目前沒有正在處理的學校事件 | 玩家尚未經過或停留學校格 | 學校事件正式成立後離開 | 等待正式事件入口、建立事件基本資料 | 直接宣告學校完成 |

| 考試處理中 | 表示玩家已決定參加考試，正在處理正式考試結果 | 玩家正式選擇參加考試 | 考試結果已正式產生後離開 | 承接考試結果、準備職業結果、標記後續幸福卡 | 略過正式考試結果 |
| 升等承接中 | 表示考試結果正交由職業系統承接 | 考試結果已產生，且需要影響職業成長 | 職業結果已正式承接後離開 | 把正式結果交由職業系統承接 | 在未承接前直接宣告職級已變更 |
| 幸福卡承接中 | 表示正在承接考後幸福卡 | 玩家已參加考試，且考後幸福卡事件已建立 | 後續幸福卡事件正式完成後離開 | 等待後續卡片完成、收束學校事件 | 在幸福卡未完成前結束學校事件 |
| 已完成 | 表示學校事件已正式結束 | 考試選擇、必要的職業承接與必要的幸福卡都已正式完成 | 無 | 交還事件完成權、允許回合系統推進 | 再次變更本次學校事件結果 |

# Rules

## 學校事件規則

- 玩家經過學校格時，必須建立一次學校事件入口。
- 玩家停留學校格時，同樣必須建立一次學校事件入口。
- 學校事件屬正式事件，必須服從事件系統的生命週期與完成條件。
- 學校事件完成前，不得切換下一位玩家。

## 考試參與規則

- 玩家在學校事件中可選擇是否參加考試。
- 若玩家不參加考試，學校事件直接結束，不抽取考後幸福卡。
- 若玩家參加考試，必須先完成考試正式結果，再處理後續幸福卡。
- 學校事件不得在玩家尚未完成正式選擇前直接收束。

## 考試結果規則

- 考試結果只可分為成功、失敗或不參加。
- 若玩家參加考試，不論成功或失敗，都視為已完成正式考試流程。
- 考試成功是否導致升等，必須交由 `PROFESSION_SYSTEM.md` 承接，不得在本文件直接改寫職級或薪資。
- 考試失敗不得產生升等結果，但仍視為已完成正式考試。

## 升等承接規則

- 升等屬職業規則，不等同於學校考試。
- 學校系統只負責提供考試結果，由 `PROFESSION_SYSTEM.md` 承接其對職級、薪資與職涯成長的正式影響。
- 在職業系統完成正式承接前，不得把考試成功直接視為職級已變更。
- 學校系統不得定義職級門檻、薪資數值或終身學習效果。

## 考後幸福卡規則

- 只要玩家參加考試，無論成功或失敗，都必須抽取一張幸福卡。
- 玩家未參加考試時，不得抽取考後幸福卡。
- 考後幸福卡屬正式卡片事件，必須由 `CARD_SYSTEM.md` 承接其抽牌、揭示、結算與完成。
- 考後幸福卡完成前，學校事件不得視為已完成。

## 完成規則

- 學校事件完成，必須同時滿足以下條件：
  - 玩家已完成是否參加考試的正式選擇
  - 若玩家參加考試，考試結果已正式產生
  - 若考試結果需要影響職業成長，職業系統已完成正式承接
  - 若玩家參加考試，考後幸福卡已正式完成
- 只要任一條件未成立，學校事件就不得完成。

## 交界規則

- `BOARD_SYSTEM.md` 只負責學校格的正式入口，不負責學校事件內部細節。
- `EVENT_SYSTEM.md` 負責學校事件的排隊、完成與阻塞模型。
- `CARD_SYSTEM.md` 負責考後幸福卡的正式卡片生命週期。
- `PROFESSION_SYSTEM.md` 負責考試結果所導致的正式升等承接。

  ->
建立學校事件
  ->

  ->

  ->

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待觸發 | 進入事件判定中 | 玩家經過或停留學校格且正式事件入口成立 | 待觸發 -> 事件判定中 | 待觸發 -> 已完成 |
| 事件判定中 | 進入已完成 | 玩家正式選擇不參加考試 | 事件判定中 -> 已完成 | 事件判定中 -> 幸福卡承接中 |
| 事件判定中 | 進入考試處理中 | 玩家正式選擇參加考試 | 事件判定中 -> 考試處理中 | 事件判定中 -> 已完成（未完成選擇前） |
| 考試處理中 | 進入升等承接中 | 考試結果已產生且需要職業系統承接 | 考試處理中 -> 升等承接中 | 考試處理中 -> 已完成 |
| 考試處理中 | 進入幸福卡承接中 | 考試結果已產生且不需要職業承接 | 考試處理中 -> 幸福卡承接中 | 考試處理中 -> 已完成 |
| 升等承接中 | 進入幸福卡承接中 | 職業系統已完成正式承接 | 升等承接中 -> 幸福卡承接中 | 升等承接中 -> 已完成 |
| 幸福卡承接中 | 進入已完成 | 考後幸福卡已正式完成 | 幸福卡承接中 -> 已完成 | 幸福卡承接中 -> 事件判定中 |
| 已完成 | 無下一正式狀態 | 學校事件已正式結束 | 無 | 重新回到考試處理中或幸福卡承接中 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 玩家經過學校格但選擇不參加考試 | 是否仍抽考後幸福卡 | 不可。未參加考試時，學校事件直接結束。 |
| 玩家停留學校格並參加考試但失敗 | 是否仍抽幸福卡 | 是。只要參加考試，無論成功或失敗都必須抽一張幸福卡。 |
| 考試結果已產生但幸福卡尚未完成 | 學校事件是否可先結束 | 不可。考後幸福卡屬學校事件正式後續流程。 |
| 考試成功但職業系統尚未承接 | 是否可直接視為升等完成 | 不可。必須先由職業系統承接正式結果。 |
| 同一回合內仍有其他正式事件 | 學校事件是否可先切換下一位玩家 | 不可。學校事件必須依事件系統完成後，才可結束當前回合。 |
| 遊戲已正式結束 | 是否可再建立學校事件 | 不可。遊戲正式結束後不得建立新的學校事件。 |

# Design Principles

- 單一職責：本文件只定義學校事件、考試、升等承接、考後幸福卡與收束條件。
- 模組化：回合、事件、卡片與職業結果分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔職業本體、薪資、卡片生命週期或棋盤移動責任。
- 高內聚：所有學校事件進入、應試、後續幸福卡與完成規則集中於本文件。
- 單一權威來源：學校系統正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴回合、事件、棋盤與卡片系統，並把職業結果交由下游系統承接。
- 依賴方向固定：學校系統承接上游入口與生命週期，並把升等結果交由下游職業系統承接。
- 資料與 UI 分離：本文件只描述正式學校資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程與執行細節。
- 產品規則不得寫進程式：學校規則調整必須先更新正式規格。

# Writing Rules

- 其他 GDD 若需要引用學校事件、考試參與與考後幸福卡規則，必須以本文件為正式來源。
