# Purpose

本文件定義《第二人生》的房屋系統正式設計，負責說明房屋、自住、出租、房屋交易、房市、房貸、房屋保險與房屋估值的正式規則。

本文件只承接 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認 Decision，不重新定義產品規則。

本文件的責任，是把已確認的房屋相關正式規則整理為可維護、可分工、可引用的系統設計，讓房屋資產、使用模式、估值、交易與附掛關係有一致的正式邊界。

# Scope

## 本文件負責

- 定義房屋的正式責任範圍
- 定義房屋的正式資料模型
- 定義房屋的正式狀態
- 定義房屋自住、出租與轉換規則
- 定義房屋交易與房屋市場規則
- 定義房貸與房屋保險的正式關聯邊界
- 定義房屋估值的正式來源與結果承接

## 本文件不負責

- 重新定義一般資產 ownership
- 重新定義正式財務檢核與月結算
- 重新定義貸款成立、還款或清償的完整規則
- 重新定義保險購買、理賠或保費的完整規則
- 重新定義市場行情更新的完整規則
- 描述任何程式、畫面、介面或技術實作

## 邊界原則

- 房屋系統只負責房屋本體、使用模式與房屋專屬語意。
- 房屋 ownership 由 `ASSET_SYSTEM.md` 承接，不在本文件重複定義。
- 房屋交易成立與金額是否可成立，由 `FINANCIAL_SYSTEM.md` 承接。
- 房貸附掛與清償，由 `LOAN_SYSTEM.md` 承接。
- 房屋估值與市場行情，由 `MARKET_SYSTEM.md` 承接。
- 房屋保險附掛與有效性，由 `INSURANCE_SYSTEM.md` 承接。

# Rules

## 房屋所有權規則

- 房屋屬正式資產，所有權由 `ASSET_SYSTEM.md` 承接。
- 同一時間同一房屋只能有一位正式持有人。
- 房屋的持有狀態不得與一般資產 ownership 分離解讀。
- 房屋失去所有權後，不得再以持有房屋的正式狀態處理。

## 自住規則

- 自住是房屋持有期間的正式使用模式之一。
- 自住房屋不以租金收入形式計入房屋結果。
- 自住狀態只改變房屋使用模式，不改變房屋所有權。
- 自住房屋仍可維持房貸與房屋保險的正式附掛。

## 出租規則

- 出租是房屋持有期間的正式使用模式之一。
- 出租房屋會形成正式租金結果，並由 `FINANCIAL_SYSTEM.md` 承接月現金流。
- 出租狀態只改變房屋使用模式，不改變房屋所有權。
- 出租房屋仍可維持房貸與房屋保險的正式附掛。

## 房屋轉換規則

- 房屋在持有期間可於自住與出租之間轉換。
- 房屋轉換不改變所有權，只改變使用模式。
- 房屋轉換所導致的租金、支出或其他財務結果，由 `FINANCIAL_SYSTEM.md` 承接。
- 房屋轉換完成前，不得同時宣告兩種使用模式都已正式成立。

## 房屋交易規則

- 房屋購買與出售屬正式房屋交易。
- 房屋交易正式完成前，不得視為房屋所有權已變更。
- 房屋交易成立與支付能力是否成立，由 `FINANCIAL_SYSTEM.md` 承接。
- 房屋交易若同時涉及房貸或房屋保險，相關附掛結果必須由對應系統同步承接。
- 房屋出售時若仍存在房貸，必須先由 `LOAN_SYSTEM.md` 處理對應關聯與清償結果。

## 房市規則

- 房市屬正式市場集合，必須使用正式房市資料結構。
- 房市不得只以卡片或編號清單作為正式房屋市場來源。
- 每筆房屋市場標的都必須可追溯來源、價格、狀態與成交結果。
- 房屋市場價格是房屋估值與房屋交易判定的正式參考。
- 尚未正式生效的房市資料，不得作為房屋正式估值依據。

## 房貸規則

- 房貸是附掛於房屋資產上的正式貸款。
- 房貸的成立、還款與清償由 `LOAN_SYSTEM.md` 承接。
- 房屋若已附掛房貸，出售時必須同步處理該附掛關係。
- 房貸只改變房屋的負債關聯，不改變房屋所有權本身。

## 房屋保險規則

- 房屋保險是附掛於房屋資產上的正式保險狀態。
- 房屋保險的購買、生效與理賠由 `INSURANCE_SYSTEM.md` 承接。
- 房屋保險的附掛對象必須是正式房屋資產。
- 房屋失去所有權時，對應房屋保險的附掛關係必須同步終止。

## 房屋估值規則

- 房屋估值以正式房市行情為唯一正式價格來源。
- 房屋估值結果必須能對應唯一正式房市標的。
- 房屋估值結果由 `ASSET_SYSTEM.md` 承接為正式資產價值。
- 未正式生效的市場行情，不得作為房屋估值或交易依據。
- 房屋估值不得自行改用其他未確認來源。

## 遊戲結束規則

- 遊戲正式結束後，不得再建立新的房屋交易、轉換、估值或附掛變更。
- 遊戲正式結束後，只能查閱既有房屋資料與既有正式結果。

# Flow

```text
開始
  ->
確認房屋市場與房屋正式來源
  ->
若為交易
  ->
進入房屋交易中
  ->
完成正式財務成立
  ->
更新房屋所有權與附掛關係
  ->
決定自住或出租
  ->
進入持有自住或持有出租
  ->
若需轉換
  ->
進入轉換中
  ->
更新使用模式
  ->
回到持有自住或持有出租
  ->
若需估值
  ->
引用正式房市行情
  ->
更新房屋估值
  ->
完成
```

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 未持有 | 進入房屋交易中 | 房屋購買或正式房屋市場承接成立 | 未持有 -> 房屋交易中 | 未持有 -> 持有自住、未持有 -> 持有出租 |
| 房屋交易中 | 進入持有自住 | 交易正式完成且使用模式為自住 | 房屋交易中 -> 持有自住 | 房屋交易中 -> 已出售（未完成前） |
| 房屋交易中 | 進入持有出租 | 交易正式完成且使用模式為出租 | 房屋交易中 -> 持有出租 | 房屋交易中 -> 轉換中（未完成交易前） |
| 持有自住 | 進入轉換中 | 正式啟動自住轉出租 | 持有自住 -> 轉換中 | 持有自住 -> 未持有 |
| 持有出租 | 進入轉換中 | 正式啟動出租轉自住 | 持有出租 -> 轉換中 | 持有出租 -> 未持有 |
| 轉換中 | 回到持有自住 | 轉換正式完成且結果為自住 | 轉換中 -> 持有自住 | 轉換中 -> 未持有 |
| 轉換中 | 回到持有出租 | 轉換正式完成且結果為出租 | 轉換中 -> 持有出租 | 轉換中 -> 未持有 |
| 持有自住 | 進入房屋交易中 | 正式出售房屋 | 持有自住 -> 房屋交易中 | 持有自住 -> 持有出租（未經轉換） |
| 持有出租 | 進入房屋交易中 | 正式出售房屋 | 持有出租 -> 房屋交易中 | 持有出租 -> 持有自住（未經轉換） |
| 房屋交易中 | 進入已出售 | 房屋出售正式完成 | 房屋交易中 -> 已出售 | 房屋交易中 -> 持有自住、房屋交易中 -> 持有出租 |
| 已出售 | 進入房屋交易中 | 新一輪正式購買成立 | 已出售 -> 房屋交易中 | 已出售 -> 持有自住、已出售 -> 持有出租 |
| 任何狀態 | 進入結束鎖定 | 遊戲正式結束 | 任何狀態 -> 結束鎖定 | 結束鎖定 -> 持有自住、結束鎖定 -> 持有出租 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 房屋在持有期間由自住切換為出租 | 是否需要改變所有權 | 不需要。只改變使用模式，所有權維持不變。 |
| 房屋在持有期間由出租切換為自住 | 是否需要改變所有權 | 不需要。只改變使用模式，所有權維持不變。 |
| 房屋出售時仍存在房貸 | 房屋所有權與負債關聯是否可分離處理 | 不可分離。必須先由 `LOAN_SYSTEM.md` 處理關聯與清償，再完成出售結果。 |
| 房屋已附掛保險後被出售 | 房屋保險是否仍可保留 | 不可保留。房屋失去所有權時，附掛關係必須同步終止。 |
| 房屋估值缺乏正式市場行情 | 是否可直接使用其他來源 | 不可。必須等待正式房市行情成立，才能形成房屋估值。 |
| 房屋市場標的尚未正式生效 | 是否可用於成交或估值 | 不可。未正式生效的市場資料不得作為正式依據。 |
| 房屋在交易中同時要求轉換自住與出租 | 是否可同時成立 | 不可。房屋交易與房屋轉換不得同時以衝突狀態成立。 |
| 遊戲正式結束後仍有房屋交易或估值請求 | 是否可繼續處理 | 不可。結束鎖定後不得再建立新的房屋正式結果。 |

# Design Principles

- 單一職責：本文件只定義房屋本體、自住、出租、轉換、交易、房市引用、房貸附掛、房屋保險附掛與房屋估值。
- 模組化：資產所有權、財務成立、貸款附掛、保險附掛與市場行情分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔一般資產 ownership、正式交易成立、行情更新或貸款清償主流程責任。
- 高內聚：所有房屋使用模式、交易、附掛與估值規則集中於本文件。
- 單一權威來源：房屋系統正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴資產、財務、貸款、市場與保險系統，不得反向要求它們依賴本文件。
- 依賴方向固定：房屋系統承接上游 ownership、交易、附掛與行情結果，不重寫其正式邊界。
- 資料與 UI 分離：本文件只描述正式房屋資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程與執行細節。
- 產品規則不得寫進程式：房屋規則調整必須先更新正式規格。

# Writing Rules

- 不得重新定義一般資產 ownership、正式財務檢核、房貸清償或市場行情生效規則。
- 不得自行補入未被上游正式文件確認的房屋價格公式、租金公式或房貸數值。
- 不得包含現況分析、問題盤點、選項比較、建議段落、待確認事項或待辦項目。
- 不得描述程式、框架、介面協定、資料庫或畫面細節。
- 若房屋效果涉及其他系統責任，必須以引用方式承接，不得複製上游規則。

# Modular Design Rules

- 本文件只負責房屋系統，不承擔資產、財務、貸款、保險或市場系統責任。
- 本文件可依賴 `docs/gdd/ASSET_SYSTEM.md`、`docs/gdd/FINANCIAL_SYSTEM.md`、`docs/gdd/LOAN_SYSTEM.md`、`docs/gdd/MARKET_SYSTEM.md`、`docs/gdd/INSURANCE_SYSTEM.md`。
- 其他 GDD 若需要引用房屋交易、自住 / 出租、房貸附掛或房屋估值規則，必須以本文件為正式來源。
- 本文件與其他 GDD 的依賴方向必須維持 DAG，不得形成循環依賴。
- 房屋正式規則只能在本文件定義一次，其他文件不得複製或改寫。
