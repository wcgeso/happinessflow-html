## Purpose

本文件定義職業系統的正式設計，負責說明職業、職級（Rank）、升等（Promotion）、薪資、職涯成長與終身學習的正式規則。

本文件的責任，是把已確認的產品規則轉化為可維護、可分工、可延伸的職業設計，並與財務系統、學校系統保持清楚邊界。

本文件不得重新定義產品規則。所有正式規則都必須以 Product Specification 與已確認的 Decision 為來源。

## Scope

### 本文件負責

- 定義職業的正式責任範圍
- 定義職級與職級序列
- 定義升等的正式條件與結果
- 定義薪資的正式來源與變更原則
- 定義職涯成長的正式收斂方式
- 定義終身學習的正式邊界

### 本文件不負責

- 重新定義學校事件本身
- 重新定義銀行事件與銀行服務窗口
- 重新定義財務檢核、收入、支出或結算
- 重新定義卡片、資產、負債或市場規則
- 描述介面細節或操作流程細節

### 邊界原則

- 職業系統只負責職涯本體，不承擔銀行、資產或市場的主責設計
- 學校系統負責學校事件本身，職業系統只承接其與職涯相關的正式結果
- 財務系統負責薪資、支出與正式財務成立條件，職業系統不得自行繞過財務規則
- 終身學習屬職業成長的獨立正式流程，不得與學校事件混為同一正式規則

## Definitions

| 名詞 | 定義 |
|---|---|
| 職業 | 玩家在本局中選定的正式職涯類別，用以決定初始職級、起始薪資與成長路徑。 |
| 職級（Rank） | 職業內的正式階段，用以表示玩家目前的職涯位置，並影響薪資與等級支出。 |
| 升等（Promotion） | 依正式條件使職級上升的流程，結果可能伴隨薪資與職涯紀錄變動。 |
| 薪資 | 與職業與職級直接連動的正式收入基礎。 |
| 職涯成長 | 玩家在同一職業中的正式進展總稱，包含職級提升、薪資調整與成長紀錄更新。 |
| 終身學習 | 不屬學校事件的獨立職涯成長流程，可能產生職級、薪資或成長紀錄的正式變化。 |
| 職業資料 | 定義某一職業之初始職級、職級序列、升等條件、薪資與成長規則的正式資料集合。 |
| 職級序列 | 某一職業可依序到達的正式職級順序。 |
| 職涯紀錄 | 記錄職業、職級、升等與薪資變動的正式歷程。 |

| 待選職 | 表示玩家尚未確立正式職業 | 本局尚未完成職業選擇 | 玩家正式選定職業後離開 | 選定職業、建立初始職級與薪資 | 升等、終身學習、套用職涯成長結果 |

| 升等處理中 | 表示玩家正在執行正式升等流程 | 升等條件已被正式觸發，且開始進行升等檢核 | 升等結果正式成立或正式失敗後離開 | 檢核條件、判定結果、套用升等變化 | 同時套用另一個升等結果、跳過正式檢核 |
| 終身學習處理中 | 表示玩家正在執行正式終身學習流程 | 終身學習流程已被正式觸發 | 終身學習結果正式成立或正式失敗後離開 | 檢核條件、判定結果、套用允許的職涯變化 | 將終身學習直接視為學校事件、跳過正式結果 |

## Rules

### 1. 職業確立規則

1. 每位玩家同一時間只可擁有一個正式職業。
2. 職業一旦確立，即決定該玩家的初始職級與初始薪資。
3. 職業資料必須明確定義其職級序列與升等路徑。
4. 若正式規則未提供轉職流程，不得以其他流程替代轉職。

### 2. 職級規則

1. 職級（Rank）屬於職業內部的正式階段。
2. 職級必須沿職級序列依序前進。
3. 職級不得跳級，除非正式職業資料明確允許。
4. 職級可影響薪資與等級支出。
5. 職級變動後，職涯紀錄必須同步更新。

### 3. 升等規則

1. 升等（Promotion）屬於職業系統的正式流程。
2. 升等只能依正式升等條件成立後進行。
3. 升等完成前，職級不得被視為已變更。
4. 升等結果必須明確包含職級變動與其正式影響。
5. 升等後的薪資變動，必須交由財務系統以正式規則承接。

### 4. 薪資規則

1. 薪資屬於職業與職級直接連動的正式收入基礎。
2. 薪資的正式來源只能來自本文件定義的職業規則。
3. 薪資變動後，財務系統必須使用最新薪資作為收入判定依據。
4. 薪資不得在未完成正式升等或正式學習結果前任意變更。
5. 若職級對應有等級支出修正，財務系統必須依正式職級結果同步調整。

### 5. 職涯成長規則

1. 職涯成長是職業系統的總稱，不是獨立於職業之外的另一套規則。
2. 職涯成長的正式結果只能表現在職級、薪資、紀錄或正式允許的成長效果上。
3. 職涯成長不得繞過升等條件。
4. 職涯成長不得繞過財務成立條件。
5. 同一玩家同一時間若存在多個職涯成長觸發，必須依正式順序逐一處理，不得並行套用。

### 6. 終身學習規則

1. 終身學習屬於獨立正式流程，不屬學校事件本體。
2. 終身學習可與職業成長共享表現節奏，但不得共享正式規則。
3. 終身學習的正式結果，只能在本文件允許的職業成長範圍內生效。
4. 終身學習若產生職級或薪資變動，必須依正式結果完成後才可生效。
5. 終身學習不得直接視為升等，除非正式結果明確指定。

## Flow

```text
開始
  ->
玩家正式選定職業
  ->
建立初始職級與初始薪資
  ->
進入職涯穩定
  ->
觸發升等條件或終身學習流程
  ->
進入對應的成長處理
  ->
檢核正式條件
  ->
套用職級、薪資與職涯紀錄變動
  ->
回到職涯穩定
  ->
完成
```

## State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待選職 | 進入職涯穩定 | 玩家正式選定職業 | 待選職 -> 職涯穩定 | 待選職 -> 升等處理中、待選職 -> 終身學習處理中 |
| 職涯穩定 | 進入升等處理中 | 升等條件正式成立 | 職涯穩定 -> 升等處理中 | 職涯穩定 -> 待選職 |
| 職涯穩定 | 進入終身學習處理中 | 終身學習流程正式觸發 | 職涯穩定 -> 終身學習處理中 | 職涯穩定 -> 待選職 |
| 升等處理中 | 回到職涯穩定 | 升等正式完成或正式失敗 | 升等處理中 -> 職涯穩定 | 升等處理中 -> 待選職 |
| 終身學習處理中 | 回到職涯穩定 | 終身學習正式完成或正式失敗 | 終身學習處理中 -> 職涯穩定 | 終身學習處理中 -> 待選職 |

## Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 同一玩家同時符合升等與終身學習條件 | 多個職涯成長結果可能同時成立 | 必須依正式觸發順序逐一處理，不得合併成單一結果。 |
| 升等已成立但薪資尚未更新 | 職級與薪資可能短暫不一致 | 升等未完成正式更新前，不得視為完整成立。 |
| 終身學習成功但未產生職級變化 | 是否一定要升等 | 不一定。終身學習只可套用正式規則允許的結果。 |
| 職級已達最終階段 | 是否仍可繼續升等 | 不可。若職級序列已結束，後續不得再以升等方式前進。 |
| 職級變動同時影響薪資與等級支出 | 變動可能分散在不同規則 | 必須視為同一正式職涯結果，並同步完成。 |
| 另一個職涯成長流程在前一流程未完成時被觸發 | 可能造成結果重疊 | 後觸發者必須等待前一流程完成後再處理。 |
| 遊戲已正式結束 | 是否仍可產生新的職涯變動 | 不可。遊戲結束後不得再建立新的正式職涯結果。 |

## Design Principles

- 單一職責：本文件只定義職業、職級、升等、薪資、職涯成長與終身學習規則。
- 模組化：學校事件與財務成立分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔銀行、資產、市場或卡片系統責任。
- 高內聚：所有職涯資料、職級序列、升等與薪資變動規則集中於本文件。
- 單一權威來源：職業系統的正式產品規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件可依賴財務與學校系統，但不得反向要求它們依賴本文件。
- 依賴方向固定：職業系統承接學校與財務結果，不重寫上游事件或交易規則。
- 資料與 UI 分離：本文件只描述正式職涯資料與規則，不描述畫面或操作元件。
- 規則與實作分離：本文件不描述技術流程與執行細節。
- 產品規則不得寫進程式：職業規則調整必須先更新正式規格。

## Writing Rules

- 不得重新定義學校事件本身或正式財務檢核規則。
- 不得把終身學習直接寫成學校事件的同義流程。
- 不得包含現況分析、問題盤點、選項比較、建議段落、待確認事項或待辦項目。
- 不得描述程式、框架、介面協定、資料庫或畫面細節。
- 若職涯結果涉及其他系統責任，必須以引用方式處理，不得複製上游規則。

## Modular Design Rules

- 本文件只負責職業系統，不承擔學校、財務、銀行、卡片或資產系統責任。
- 本文件可依賴 `docs/gdd/FINANCIAL_SYSTEM.md` 與 `docs/gdd/SCHOOL_SYSTEM.md`，不得反向依賴下游文件。
- 其他 GDD 若需要引用職級、升等或薪資邊界，必須以本文件為正式來源。
- 本文件與其他 GDD 的依賴方向必須維持 DAG，不得形成循環依賴。
- 正式職涯規則只能在本文件定義一次，其他文件不得複製或改寫。
