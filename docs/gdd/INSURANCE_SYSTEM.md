# Purpose

本文件定義保險系統的正式設計。

本文件只負責說明醫療保險、房屋保險、汽車保險、保費、理賠、保險狀態、保險與資產附掛、保險與 Financial Check、保險事件流程的正式規則與正式資料模型。

本文件不得重新定義產品規則。

所有保險相關正式規則皆以 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認 Decision 為正式來源。本文件僅承接上游規則，將其整理為保險系統的正式設計。

# Scope

## 本文件負責

- 定義保險系統的正式責任範圍
- 定義醫療保險、房屋保險、汽車保險的正式分類
- 定義保費與月支出的正式關係
- 定義理賠的正式結果與交易紀錄關係
- 定義保險狀態與附掛狀態
- 定義保險購買、理賠與月結算的正式流程
- 定義保險系統的正式 State 與狀態轉換

## 本文件不負責

- 重新定義銀行事件或銀行服務窗口流程
- 重新定義財務檢核成立條件
- 重新定義資產所有權或資產估值規則
- 重新定義棋盤、卡片或其他事件系統的入口規則
- 建立獨立的 Insurance Object
- 建立獨立的 Claim Ledger
- 描述任何程式、畫面或技術實作

## 邊界原則

- 保險購買入口由 `BANK_SYSTEM.md` 負責，保險成立條件由 `FINANCIAL_SYSTEM.md` 負責，附掛關係由 `ASSET_SYSTEM.md` 承接。
- 本文件只定義保險類型、保費、理賠與保險狀態的正式語意，不重複定義資產所有權與財務成立條件。
- 理賠結果必須以正式交易紀錄保存，不以獨立理賠台帳作為正式來源。

# State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 未投保 | 表示目前沒有有效保險 | 尚未建立保險，或保險已正式終止 | 成功購買保險後離開 | 提出保險購買、查閱保險條件 | 宣告保費生效、提出有效理賠 |
| 投保待生效 | 表示保險已正式購買，但尚未到生效結算點 | 保險購買已通過正式檢核，且尚未經過下一次月結算 | 下一次月結算完成後離開 | 等待生效、準備保費計入、保留附掛關係 | 宣告為有效、跳過保費開始時點 |
| 有效 | 表示保險已正式生效 | 已通過生效結算點，且保險仍符合正式條件 | 進入理賠處理中或正式終止時離開 | 計入保費、提出理賠、維持附掛狀態 | 以未生效狀態理賠、忽略保費 |
| 理賠處理中 | 表示理賠事件正在正式處理 | 有效保險已建立正式理賠入口 | 理賠正式完成後離開 | 執行理賠檢核、寫入交易紀錄、更新理賠結果 | 直接跳過財務檢核、直接完成理賠 |
| 已終止 | 表示該筆保險不再有效 | 保險因正式規則終止，或附掛資產已失去對應關係 | 新的正式保險購買成立後離開 | 保留理賠與購買歷史、等待重新投保 | 計入保費、提出有效理賠 |

# Rules

## 保險類型規則

- 正式保險只分為三類：
  - 醫療保險
  - 房屋保險
  - 汽車保險
- 保險不是獨立資產。
- 房屋保險與汽車保險必須附掛於對應資產。
- 醫療保險以數量表示，不以獨立資產表示。
- 汽車保險只對應汽車，不得以其他正式名稱取代。

## 保險購買規則

- 保險購買屬正式金融交易，必須通過 `FINANCIAL_SYSTEM.md` 定義的 Financial Check 後才可正式成立。
- 保險購買屬於需要銀行服務窗口的正式操作。
- 保險購買成功後，保險必須先進入投保待生效狀態。
- 保險購買完成後，不得立即視為有效，必須等待下一次月結算到達生效結算點。
- 醫療保險的購買結果以有效數量更新。
- 房屋保險與汽車保險的購買結果以對應資產的附掛狀態更新。

## 保費規則

- 保費屬正式月支出，必須納入 `FINANCIAL_SYSTEM.md` 的月結算。
- 醫療保險保費依有效數量計入。
- 房屋保險與汽車保險保費依對應有效附掛狀態計入。
- 已購買但尚未到生效結算點的保險，不得計入當期保費。
- 保費開始計入後，必須持續反映在正式支出與月結算結果中。

## 附掛規則

- 房屋保險只能附掛於房屋資產。
- 汽車保險只能附掛於汽車資產。
- 同一筆房屋資產同一時間只能有一份有效房屋保險。
- 同一筆汽車資產同一時間只能有一份有效汽車保險。
- 保險附掛關係必須與 `ASSET_SYSTEM.md` 的正式資產所有權一致。
- 附掛資產若失去所有權，附掛於該資產的保險狀態必須同步終止。

## 理賠規則

- 理賠屬正式保險事件，不是獨立理賠台帳。
- 理賠完成前，不得視為正式成立。
- 理賠必須通過 `FINANCIAL_SYSTEM.md` 定義的 Financial Check 後才可正式成立。
- 理賠結果必須以正式交易紀錄保存。
- 不建立獨立 Claim Ledger。
- 理賠完成後，該筆理賠的正式結果必須回寫到對應保險狀態與交易紀錄。
- 若理賠使醫療保險數量或附掛保險狀態發生變動，該變動必須在正式理賠結果中同步反映。

## 銀行服務窗口規則

- 銀行服務窗口只約束保險購買入口，不作為理賠成立條件。
- 保險理賠是否成立，只依本文件與 `FINANCIAL_SYSTEM.md` 的正式規則判定。
- 銀行服務窗口到期後，不影響已正式成立的保險或已正式完成的理賠紀錄。

## 月結算與狀態規則

- 每次月結算時，系統必須先辨識有效保險數量與有效附掛保險，再計入對應保費。
- 投保待生效狀態的保險在到達生效結算點前，不得作為有效保險處理。
- 已終止的保險不得再計入保費或提出有效理賠。
- 理賠處理中的保險，在理賠正式完成前，仍以原正式狀態判定是否可計入保費。

# Flow

```text
保險購買開始
  ->
確認保險類型
  ->
確認銀行服務窗口
  ->
完成 Financial Check
  ->
建立保險附掛或醫療數量
  ->
進入投保待生效
  ->
下一次月結算
  ->
進入有效
  ->
完成
```

```text
理賠入口成立
  ->
確認保險有效
  ->
進入理賠處理中
  ->
完成 Financial Check
  ->
寫入正式交易紀錄
  ->
更新對應保險狀態
  ->
完成
```

```text
月結算開始
  ->
辨識有效醫療保險數量
  ->
辨識有效房屋與汽車附掛保險
  ->
計入保費支出
  ->
更新正式月支出
  ->
完成
```

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 未投保 | 進入投保待生效 | 保險購買通過正式檢核 | 未投保 -> 投保待生效 | 未投保 -> 有效、未投保 -> 理賠處理中 |
| 投保待生效 | 進入有效 | 下一次月結算完成，且保險到達生效結算點 | 投保待生效 -> 有效 | 投保待生效 -> 理賠處理中 |
| 有效 | 進入理賠處理中 | 有效保險建立正式理賠入口 | 有效 -> 理賠處理中 | 有效 -> 未投保 |
| 理賠處理中 | 回到有效 | 理賠正式完成，且該筆保險仍持續有效 | 理賠處理中 -> 有效 | 理賠處理中 -> 未投保 |
| 有效 | 進入已終止 | 附掛資產失去所有權，或保險正式終止 | 有效 -> 已終止 | 有效 -> 投保待生效 |
| 投保待生效 | 進入已終止 | 保險在生效前即正式終止 | 投保待生效 -> 已終止 | 投保待生效 -> 理賠處理中 |
| 已終止 | 重新投保 | 新的正式保險購買成立 | 已終止 -> 投保待生效 | 已終止 -> 有效、已終止 -> 理賠處理中 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 保險購買已成功但尚未到下一次月結算 | 是否可立即視為有效 | 不可以。必須先進入投保待生效，並於下一次月結算後才成為有效。 |
| 同一筆房屋或汽車資產再次投保 | 是否可建立第二份有效附掛保險 | 不可以。同一資產同時只允許一份有效房屋保險或汽車保險。 |
| 附掛資產在保險有效期間內被出售 | 保險狀態是否仍可保留 | 不可保留。附掛於該資產的保險狀態必須同步終止。 |
| 醫療保險數量為零 | 是否仍可提出理賠 | 不可以。沒有有效數量時，不得成立有效理賠。 |
| 理賠完成後仍有相同保險狀態 | 是否需要重建保險 | 不需要。若保險仍符合正式條件，理賠完成後回到有效狀態。 |
| 月結算時保費超過可用現金 | 保費是否可被跳過 | 不可跳過。保費仍須記入正式月支出，後續不足處理由財務系統承接。 |
| 理賠與月結算在同一輪發生 | 是否可任意交換順序 | 不可任意交換。必須依正式事件與月結算順序逐一完成，不能跳過正式檢核。 |
| 銀行服務窗口已失效 | 是否可繼續購買保險 | 不可以。需要銀行服務窗口的保險購買不得在失效後成立。 |

# Design Principles

- 單一職責：本文件只定義保險類型、保費、理賠、附掛與狀態規則。
- 模組化：銀行入口、資產附掛與財務成立分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔銀行事件、資產估值、棋盤入口或回合流程責任。
- 高內聚：所有保險有效性、生效時點、保費與理賠規則集中於本文件。
- 單一權威來源：保險正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴銀行、財務與資產系統，不得要求它們反向依賴本文件。
- 依賴方向固定：保險系統承接上游權限與成立條件，並提供下游房屋與維修等系統引用。
- 資料與 UI 分離：本文件只描述正式保險資料與規則，不描述畫面或操作元件。
- 規則與實作分離：本文件不描述技術實作流程。
- 產品規則不得寫進程式：保險規則調整必須先更新正式規格。
