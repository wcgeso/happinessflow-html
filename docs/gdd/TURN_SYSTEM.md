# Purpose

本文件定義回合系統的正式設計。

本文件只負責說明單一回合如何開始、如何由當前玩家持有操作權、在何種條件下被阻塞、在何種條件下視為完成，以及跳過回合的正式處理方式。

本文件不得重新定義產品規則。

所有回合規則皆以 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認的 Decision 為正式來源。本文件僅承接上游規則，將其整理為回合系統的正式設計。

# Scope

## 本文件負責

- 定義回合生命週期
- 定義回合操作權
- 定義回合完成條件
- 定義回合阻塞條件
- 定義跳過回合規則
- 定義回合狀態機

## 本文件不負責

- 定義棋盤格效果內容
- 定義卡片抽取、揭示與結算內容
- 定義銀行服務內容
- 定義財務檢核結算內容
- 定義資產、保險、貸款或市場規則
- 定義多人共同參與事件的細部規則

## 邊界原則

- 回合系統只負責「何時可以前進到下一步」。
- 事件內容由 `EVENT_SYSTEM.md` 與其下游 GDD 負責。
- 棋盤移動與格子入口由 `BOARD_SYSTEM.md` 負責。
- 卡片生命週期由 `CARD_SYSTEM.md` 負責。

# Definitions

| 名詞 | 定義 |
|---|---|
| 回合 | 單一玩家自取得當前回合操作權起，到正式失去該操作權為止的完整流程。 |
| 回合生命週期 | 回合從開始、進行、阻塞、完成到切換的正式變化順序。 |
| 當前回合玩家 | 目前持有回合主要操作權，並負責執行本回合必要步驟的玩家。 |
| 回合操作權 | 在回合中執行正式回合步驟的權利。 |
| 回合阻塞 | 因未完成的正式事件、後續事件或財務處理，導致回合不得進入下一階段或不得切換下一位玩家的狀態。 |
| 回合完成 | 本回合所有必要步驟、必要事件與必要財務處理皆已完成的狀態。 |
| 跳過回合 | 玩家因正式規則要求，在其下一個回合中不執行擲骰與移動，並直接結束該回合。 |
| 必要事件 | 由本回合移動、停留、卡片或正式事件鏈所產生，且在回合切換前必須完成的事件。 |
| 後續事件 | 由當前事件再產生、仍屬同一回合責任範圍的正式事件。 |
| 回合切換 | 當前回合正式完成後，將下一個回合操作權交給下一位玩家。 |

# Data Model

| 欄位名稱 | 型別 | 用途 | 限制 | 說明 |
|---|---|---|---|---|
| currentTurnPlayer | PlayerReference | 表示目前持有回合操作權的玩家 | 同一時間只能有一位 | 為回合系統的正式當前玩家標記 |
| turnStatus | TurnStatus | 表示回合目前所處正式狀態 | 必須為本文件定義的正式狀態之一 | 用於判定回合是否可前進、阻塞或切換 |
| skipNextTurn | Boolean | 表示玩家是否必須跳過其下一個回合 | 只作用於下一次輪到該玩家的回合 | 由醫院、維修廠或其他正式規則產生 |
| requiredEventCount | Integer | 表示本回合尚待完成的必要事件數量 | 不得為負數 | 僅描述正式責任，不描述技術實作 |
| blockingReason | TurnBlockingReason 或 Null | 表示目前回合被阻塞的正式原因 | 無阻塞時應為空值 | 用於區分事件阻塞、財務阻塞或跳過回合處理 |
| turnSequence | Integer | 表示本局進行中的回合序號 | 應隨每次正式切換遞增 | 用於辨識回合先後順序 |

# State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待開始 | 表示下一位玩家即將取得回合操作權 | 前一回合已正式完成 | 當前玩家取得回合操作權後離開 | 指派當前回合玩家、檢查是否需跳過回合 | 擲骰、切換下一位玩家 |
| 跳過回合處理中 | 表示玩家本回合需直接略過 | 玩家被正式標記為跳過下一回合，且輪到該玩家開始回合 | 跳過處理完成後離開 | 清除本次跳過資格、直接進入回合完成判定 | 擲骰、移動、建立新的回合事件 |
| 進行中 | 表示當前玩家正在執行正式回合步驟 | 回合已開始且無立即跳過 | 進入阻塞中或已滿足完成條件時離開 | 擲骰、移動、推進本回合步驟、建立必要事件 | 提前切換下一位玩家 |
| 阻塞中 | 表示回合因正式未完成事項而暫停在當前玩家 | 進行中回合產生未完成必要事件、後續事件或必要財務處理 | 所有阻塞原因清除後離開 | 完成阻塞事件、完成必要財務處理 | 切換下一位玩家、開始新回合 |
| 待完成 | 表示回合主要步驟已走完，正檢查是否可正式完成 | 本回合必要步驟皆已執行完畢 | 通過完成條件檢查後離開 | 檢查是否仍有必要事件或必要財務處理 | 建立新的非必要回合步驟 |
| 已完成 | 表示當前玩家的回合已正式結束 | 已無未完成必要事件，且必要財務處理完成 | 完成回合切換後離開 | 進行回合切換 | 再次擲骰、再次移動、重開本回合事件 |

# Rules

## 回合生命週期規則

- 玩家回合必須依正式順序進行：擲骰、玩家移動、經過格子事件、停留格子事件、所有必須處理事件、財務檢核、回合正式結束、切換下一位玩家。
- 回合的正式結束點，不得早於本回合所有必要事件與必要財務處理完成的時間點。
- 回合切換只能發生在回合已完成之後。

## 回合操作權規則

- 同一時間只能有一位當前回合玩家。
- 只有當前回合玩家可以推進本回合的正式回合步驟。
- 非當前回合玩家不得替當前回合玩家執行擲骰、移動、揭示其卡片或推進其回合完成。
- 若有共同參與事件，其他玩家只可處理屬於自己回覆責任的部分，不因此取得當前回合操作權。

## 回合完成規則

- 回合完成必須同時滿足以下條件：
  - 本回合必要步驟已全部執行
  - 本回合產生的必要事件已全部完成
  - 本回合產生的後續事件已全部完成
  - 本回合要求的必要財務處理已全部完成
- 只要其中任一條件未滿足，回合不得視為完成。
- 回合已完成後，才可切換下一位玩家。

## 回合阻塞規則

- 只要本回合仍存在未完成的必要事件，回合即為阻塞中。
- 只要本回合事件鏈仍存在未完成的後續事件，回合即為阻塞中。
- 只要本回合尚有必要財務處理未完成，回合即為阻塞中。
- 事件是否已完成，以正式規則結果為準，不以單純顯示或播放結束為準。
- 回合阻塞期間，禁止切換下一位玩家。

## 跳過回合規則

- 跳過回合只作用於被標記玩家的下一個正式回合。
- 玩家進入跳過回合時，不執行擲骰與移動。
- 跳過回合仍屬一個正式回合，必須先開始，再完成，最後才切換下一位玩家。
- 若跳過回合同時不存在其他必要事件與必要財務處理，則可直接視為回合完成。
- 跳過資格在該次回合處理完畢後即失效，不得延續到後續回合，除非又被新的正式規則再次賦予。

## 回合與事件交界規則

- 經過格子事件、停留格子事件、卡片事件與後續事件，都屬於當前回合的一部分。
- 後續事件屬正式事件，不得視為例外流程。
- 家庭歷程共同參與屬正式多人事件；所有符合資格玩家完成回覆前，當前回合不得結束。
- 學校、醫院、維修廠等正式事件只要尚未完成，即阻塞當前回合。

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待開始 | 進入跳過回合處理中 | 輪到該玩家且其具有跳過下一回合效果 | 待開始 -> 跳過回合處理中 | 待開始 -> 已完成 |
| 待開始 | 進入進行中 | 輪到該玩家且其無跳過下一回合效果 | 待開始 -> 進行中 | 待開始 -> 阻塞中 |
| 跳過回合處理中 | 進入待完成 | 跳過回合的正式略過處理完成 | 跳過回合處理中 -> 待完成 | 跳過回合處理中 -> 進行中 |
| 進行中 | 進入阻塞中 | 產生未完成必要事件、後續事件或必要財務處理 | 進行中 -> 阻塞中 | 進行中 -> 已完成 |
| 進行中 | 進入待完成 | 本回合必要步驟已完成且無阻塞項目 | 進行中 -> 待完成 | 進行中 -> 待開始 |
| 阻塞中 | 回到進行中 | 阻塞項目已清除，且仍有未完成回合步驟 | 阻塞中 -> 進行中 | 阻塞中 -> 待開始 |
| 阻塞中 | 進入待完成 | 所有阻塞項目已清除，且回合必要步驟已全部完成 | 阻塞中 -> 待完成 | 阻塞中 -> 已完成 |
| 待完成 | 進入已完成 | 完成條件全部滿足 | 待完成 -> 已完成 | 待完成 -> 待開始 |
| 已完成 | 進入待開始 | 回合正式切換至下一位玩家 | 已完成 -> 待開始 | 已完成 -> 進行中 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 當前玩家完成移動後立即產生多個事件 | 回合是否可先切換再補事件 | 不可。所有必要事件必須在同一回合內依序完成後，才可切換下一位玩家。 |
| 事件完成後又產生後續事件 | 回合是否可先視為完成 | 不可。後續事件仍屬同一回合責任範圍，必須完成後才可結束。 |
| 家庭歷程共同參與仍有人未回覆 | 當前玩家是否可先結束回合 | 不可。所有符合資格玩家都完成回覆後，回合才可繼續完成。 |
| 玩家被要求跳過下一回合 | 是否仍算一個正式回合 | 是。該回合直接略過擲骰與移動，但仍須經過回合開始、完成與切換。 |
| 跳過回合時沒有其他事件 | 是否可直接切換下一位玩家 | 可以，但必須先完成跳過回合處理，再以正式完成後的切換方式前進。 |
| 本回合必要財務處理尚未完成 | 是否可先切換下一位玩家 | 不可。必要財務處理屬回合完成條件之一。 |
| 非當前回合玩家試圖推進他人回合 | 是否可視為共同參與 | 不可。除共同參與事件中的個別回覆外，非當前回合玩家不得推進他人回合。 |
| 遊戲已正式結束 | 是否可再開始新回合 | 不可。遊戲結束後不得再建立新的正式回合。 |

# Design Principles

## 單一職責（Single Responsibility）

- 本文件只定義回合系統。
- 本文件不承擔事件、棋盤、卡片、銀行或財務內容本身的主責設計。

## 模組化（Modular Design）

- 回合系統可被其他系統引用作為共同上游。
- 下游系統應引用本文件的回合完成與阻塞規則，而不是重複定義。

## 低耦合（Low Coupling）

- 本文件只保留對產品規格與已確認決策的必要依賴。
- 本文件不引入與回合生命週期無關的細節責任。

## 高內聚（High Cohesion）

- 本文件全部章節都服務於回合生命週期、操作權、完成條件、阻塞條件與狀態轉換。

## 單一權威來源（Single Source of Truth）

- 回合正式規則以 `docs/spec/PRODUCT_SPECIFICATION.md` 為唯一產品來源。
- 回合相關產品拍板以已確認的 Decision 為唯一決策來源。

## 不可循環依賴（No Circular Dependency）

- 本文件作為核心上游文件，不反向依賴事件、棋盤或卡片細部規則。

## 依賴方向固定（Top-down Dependency）

- 依賴方向為 `Product Specification -> Decision -> TURN_SYSTEM -> 下游 GDD`。

## 資料與 UI 分離

- 本文件僅定義正式回合資料模型與狀態，不描述任何畫面呈現方式。

## 規則與實作分離

- 本文件只描述正式回合設計，不描述任何實作方式。

## 產品規則不得寫進程式

- 回合規則必須先由正式文件定義，再由其他下游文件與實作承接。

# Writing Rules

1. 本文件不得重新定義產品規則。
2. 本文件不得包含未定案討論、現況分析、歷史相容說明、待辦事項或規格辯論內容。
3. 本文件不得描述實作內容。
4. 本文件不得描述技術框架。
5. 本文件不得描述畫面細節。
6. 本文件不得描述介面串接細節。
7. 本文件不得描述資料儲存細節。
8. 本文件不得重新開啟產品討論。
9. 凡已由 `docs/spec/PRODUCT_SPECIFICATION.md` 定義的產品規則，本文件僅承接引用。
10. 凡已由 Confirmed Decision 定義的決策，本文件僅承接引用。
11. 本文件不得重複定義事件、棋盤、卡片、銀行與財務系統的主責內容。
12. 若規則跨模組，本文件以引用其他 GDD 的方式處理，不複製下游內容。

# Modular Design Rules

- 一份 GDD 只負責一個系統；本文件只負責回合系統。
- 本文件可作為多份下游 GDD 的共同上游。
- 本文件不得反向依賴其下游 GDD。
- 本文件不得與其他 GDD 形成循環依賴。
- 回合正式規則只能由一份正式 GDD 定義一次。
- 下游 GDD 必須引用本文件，不得複製本文件中的回合完成、阻塞與切換定義。
