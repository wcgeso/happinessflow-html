## Purpose

本文件定義市場系統的正式設計，負責說明股票市場、房市、企業市場、正式市場價格、正式市場更新、股利與行情來源。

本文件只承接 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認 Decision，不重新定義產品規則。

市場系統的正式責任是把可被下游引用的行情、更新與股利結果整理成單一正式設計，讓資產估值、新聞卡結果與市場相關事件有一致的正式來源。

## Scope

### 本文件負責

- 定義正式市場標的與市場分類
- 定義正式市場價格與行情來源
- 定義市場更新的正式流程與完成條件
- 定義股利的正式來源與結果歸屬
- 定義股票市場、房市、企業市場的正式責任邊界
- 定義市場系統的正式 State 與狀態機

### 本文件不負責

- 重新定義回合順序
- 重新定義卡片抽牌、揭示與結算生命週期
- 重新定義財務檢核與交易成立條件
- 重新定義資產所有權、資產出售或資產附掛
- 重新定義銀行服務窗口或銀行事件
- 描述任何畫面、介面、操作元件或程式實作

### 邊界原則

- 股票、房屋與企業的正式價格來源由市場系統定義，但其持有權與交易成立由其他系統承接
- 由新聞卡、正式事件或正式公告產生的市場變動，必須先完成對應上游生命週期，再進入市場更新
- 市場系統只負責行情、更新、股利與來源，不負責資產 ownership

## Definitions

| 名詞 | 定義 |

| 市場標的 | 會受到正式行情或股利影響的正式對象，包含股票、房屋與企業 |
| 市場行情 | 某一市場標的在某一時點的正式價格或正式條件 |
| 市場價格 | 可供估值、交易與結果判定使用的正式價格 |
| 行情來源 | 可正式改變市場行情的來源，且必須可追溯 |
| 市場更新 | 將行情來源轉換為正式行情變化的流程 |
| 股利 | 依正式持有基準產生的市場分配結果，包含現金股利與股票股利 |
| 現行行情 | 目前生效中的正式市場價格 |
| 前次行情 | 供走勢比較的上一筆正式市場價格，不得取代現行行情 |
| 行情生效 | 市場更新已完成，且可被下游系統引用的狀態 |

| marketItemId | 文字 | 識別單一市場標的 | 同一市場內不得重複 | 可對應股票代碼、房屋標的或企業標的 |
| marketSegment | 列舉 | 標示市場所屬分類 | 僅能是股票市場、房市、企業市場之一 | 用於區分不同市場責任 |
| currentPrice | 數值 | 表示當前正式行情 | 不得為負數 | 作為估值與結果判定的正式依據 |
| previousPrice | 數值 | 表示前次正式行情 | 只可作比較用途 | 不得取代 currentPrice |
| updateSource | 來源描述 | 記錄行情來源 | 必須可追溯到正式來源 | 可對應正式事件、正式卡片或正式公告 |
| updateStatus | 列舉 | 表示行情更新狀態 | 僅能使用本文件定義狀態 | 用於管理待更新、待揭示、更新中與已生效 |

| dividendBasis | 依據描述 | 記錄股利計算依據 | 必須可回溯到正式持有基準 | 用於說明股利如何產生 |
| dividendResult | 結果描述 | 保存股利的正式結果 | 只可在股利生效後寫入 | 用於表示現金增加或持有量增加 |

## State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待更新 | 表示市場目前沒有新的正式行情變動 | 現行行情已生效，且尚無新的正式來源 | 收到新的正式行情來源後離開 | 接收正式來源、等待更新 | 直接改寫現行行情 |
| 待揭示 | 表示行情來源已成立，但尚未正式公開 | 來源屬於必須揭示的正式卡片或正式事件 | 完成揭示後離開 | 等待揭示完成、準備更新 | 先行生效、先行套用結果 |
| 更新中 | 表示正式行情正在套用 | 來源已可正式處理，且更新流程已開始 | 市場行情與股利結果寫入正式資料後離開 | 套用價格、套用股利、寫入更新紀錄 | 跳過來源驗證、跳過更新紀錄 |
| 已生效 | 表示最新正式行情可供下游引用 | 更新完成且結果已正式成立 | 下一筆正式來源成立後離開 | 提供正式行情、提供正式股利結果 | 使用未生效來源、忽略前次行情 |
| 結束鎖定 | 表示遊戲已正式結束 | 遊戲正式結束 | 無 | 只允許讀取既有市場結果 | 任何新更新、新股利與新行情 |

## Rules

### 市場標的規則

1. 市場標的只分為三個正式市場分類：
   - 股票市場
   - 房市
   - 企業市場
2. 每一個市場標的都必須有唯一正式識別。
3. 每一個市場標的都必須能對應到正式價格或正式條件。
4. 同一市場標的不得同時存在多個正式現行行情。

### 行情來源規則

1. 行情來源必須是正式且可追溯的來源。
2. 行情來源可以來自正式卡片、正式事件、正式公告或已確認的上游正式規則。
3. 若行情來源屬於必須揭示的正式卡片或正式事件，必須先揭示，才可正式生效。
4. 未揭示的來源不得作為正式現行行情。
5. 行情來源不得直接改變資產 ownership。

### 市場更新規則

1. 市場更新必須先完成來源確認，再完成行情生效。
2. 市場更新完成前，前次行情仍為唯一正式可引用行情。
3. 市場更新完成後，必須保存前次行情與更新結果。
4. 同一次市場更新若影響多個市場標的，必須逐一保留正式結果。
5. 市場更新不得跳過正式來源，也不得跳過正式紀錄。

### 股票市場規則

1. 股票市場的正式行情必須可被單獨識別。
2. 股票的正式估值只能引用股票市場的正式行情。
3. 股票市場的前次行情只可作為走勢比較，不得作為正式估值依據。
4. 股票股利與股票價格變動都屬於股票市場的正式結果，必須能追溯到正式來源。

### 房市規則

1. 房市必須具備正式市場資料結構，不能只以卡號清單作為正式行情來源。
2. 每一筆房市標的都必須能表達標的識別、正式價格、正式來源與正式狀態。
3. 房市更新完成前，房市標的不得被視為正式生效。
4. 房市的正式價格只能引用房市的正式行情，不得混用股票或企業行情。

### 企業市場規則

1. 企業市場必須具備正式市場資料結構，不能只用新聞卡結果代替正式行情。
2. 每一筆企業標的都必須能表達標的識別、正式價格、正式來源與正式狀態。
3. 企業市場更新完成前，企業標的不得被視為正式生效。
4. 企業市場的正式價格只能引用企業市場的正式行情，不得混用其他市場行情。

### 股利規則

1. 股利分為現金股利與股票股利。
2. 股利必須能對應正式市場標的與正式持有基準。
3. 現金股利的正式結果是現金增加。
4. 股票股利的正式結果是持有量增加。
5. 股利不得在未正式生效前直接成為正式結果。
6. 股利結果必須寫入市場更新紀錄，並可供下游系統引用。

### 遊戲結束規則

1. 遊戲正式結束後，不得再建立新的市場更新。
2. 遊戲正式結束後，不得再生效新的行情來源。
3. 遊戲正式結束後，不得再產生新的正式股利結果。
4. 遊戲正式結束後，只能查閱既有市場資料。

## Flow

```text
開始
  ->
接收正式行情來源
  ->
判定是否需要揭示
  ->
若需要揭示，先完成揭示
  ->
確認市場標的與行情對應
  ->
更新正式價格與股利結果
  ->
寫入正式市場紀錄
  ->
提供下游系統引用
  ->
完成
```

## State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待更新 | 進入待揭示 | 收到必須揭示的正式行情來源 | 待更新 -> 待揭示 | 待更新 -> 已生效 |
| 待更新 | 進入更新中 | 收到可直接生效的正式行情來源 | 待更新 -> 更新中 | 待更新 -> 結束鎖定 |
| 待揭示 | 進入更新中 | 揭示完成 | 待揭示 -> 更新中 | 待揭示 -> 已生效 |
| 更新中 | 進入已生效 | 正式價格與股利結果已寫入 | 更新中 -> 已生效 | 更新中 -> 待更新 |
| 已生效 | 進入待更新 | 下一筆正式行情來源成立 | 已生效 -> 待更新 | 已生效 -> 結束鎖定 |
| 任何狀態 | 進入結束鎖定 | 遊戲正式結束 | 任何狀態 -> 結束鎖定 | 結束鎖定 -> 待更新、結束鎖定 -> 更新中 |

## Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 行情來源需要揭示但尚未揭示 | 行情可能被誤認為已生效 | 必須先完成揭示，才可進入更新中與已生效 |
| 同一次更新同時影響股票、房市與企業 | 多個標的可能只更新一部分 | 每個市場標的都必須獨立保留來源、價格與結果 |
| 前次行情與現行行情不一致 | 走勢判讀可能混淆 | 以現行行情為正式權威，前次行情只供比較 |
| 房市只有標的清單，沒有正式價格 | 可能被誤當成正式行情 | 不得視為正式行情，直到補齊正式價格與來源 |
| 企業標的尚未正式生效 | 可能被提前用於估值 | 必須維持在待更新或待揭示，直到正式更新完成 |
| 股利同時伴隨價格變動 | 結果可能被拆成不同來源 | 價格變動與股利結果都必須分別記錄，但仍屬同一次正式市場更新 |
| 遊戲已正式結束 | 仍可能收到新的行情來源 | 不得再建立新市場更新，只能保留查閱用途 |

## Design Principles

- 單一職責：本文件只定義市場標的、行情來源、行情更新、股利與市場估值邊界。
- 模組化：卡片揭示、棋盤入口、財務成立與資產估值分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔回合、事件、資產所有權或交易成立主流程責任。
- 高內聚：所有股票市場、房市、企業市場與股利規則集中於本文件。
- 單一權威來源：正式市場規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件可依賴卡片、棋盤、財務與資產系統，但不得形成反向依賴。
- 依賴方向固定：市場系統承接上游事件來源，並供房屋與企業等下游系統引用。
- 資料與 UI 分離：本文件只描述正式市場資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程或同步細節。
- 產品規則不得寫進程式：市場規則調整必須先更新正式規格。

## Writing Rules

- 不得重新定義市場行情卡的抽牌、揭示與完成流程。
- 不得把同步副本或前次行情寫成正式估值權威。
- 不得包含現況分析、問題盤點、選項比較、建議段落、待確認事項或待辦項目。
- 不得描述程式、框架、介面協定、資料庫或畫面細節。
- 若市場規則涉及其他系統責任，必須以引用方式處理，不得重複撰寫上游規則。

## Modular Design Rules

- 本文件只負責市場系統，不承擔卡片、財務、資產、房屋或企業系統責任。
- 本文件可依賴 `docs/gdd/CARD_SYSTEM.md`、`docs/gdd/BOARD_SYSTEM.md`、`docs/gdd/FINANCIAL_SYSTEM.md`、`docs/gdd/ASSET_SYSTEM.md`，不得反向依賴下游文件。
- 下游 GDD 若需要引用股票、房市或企業市場行情，必須以本文件為正式來源。
- 本文件與其他 GDD 的依賴方向必須維持 DAG，不得形成循環依賴。
- 正式市場規則只能在本文件定義一次，其他文件不得複製或改寫。
