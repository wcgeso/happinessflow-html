# Purpose

本文件負責定義卡片系統的正式設計。

本文件只描述卡片、牌堆、抽牌、揭示、結算、棄置、後續卡與家庭卡的正式規則、正式資料模型與正式狀態。

本文件不得重新定義產品規則。

所有卡片玩法、卡片生命周期、家庭歷程多人參與、後續卡地位與回合阻塞原則，皆直接引用 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認 Decision。

# Scope

## 本文件負責

- 定義正式卡片類別
- 定義正式牌堆與棄牌結構
- 定義抽牌、揭示、結算、完成與棄置流程
- 定義後續卡的正式地位
- 定義家庭卡的正式責任邊界
- 定義卡片事件的資料模型、狀態與狀態機
- 定義卡片系統與其他 GDD 的依賴關係

## 本文件不負責

- 重新定義回合完成條件
- 重新定義事件三層模型
- 重新定義財務檢核成立條件
- 重新定義市場價格權威
- 重新定義幸福值計分
- 重新定義家庭歷程獎勵數值以外的上游產品規則

## 邊界原則

- 回合切換與回合阻塞由 `TURN_SYSTEM.md` 定義
- 正式事件模型與正式事件完成條件由 `EVENT_SYSTEM.md` 定義
- 停留哪一種格子會進入哪一種卡片入口由 `BOARD_SYSTEM.md` 定義
- 涉及金額、資產、負債、月支出或財務檢核的結果由 `FINANCIAL_SYSTEM.md` 承接
- 幸福值與家庭歷程結果的最終歸屬分別由 `HAPPINESS_SYSTEM.md` 與 `FAMILY_SYSTEM.md` 承接

# Definitions

| 名詞 | 定義 |
|---|---|
| 卡片系統 | 負責管理正式牌堆、卡片生命周期、卡片事件與卡片所有權的系統 |
| 正式牌堆 | 可被抽取的卡片集合，包含幸福卡牌堆、機運卡牌堆與新聞卡牌堆 |
| 有效牌堆 | 目前仍可抽取的牌堆內容 |
| 已用牌堆 | 已被抽出且尚未重新洗回有效牌堆的卡片集合 |
| 棄置 | 卡片完成後離開當前事件並進入已用牌堆的正式結果 |
| 抽牌 | 從有效牌堆取出一張卡片並建立正式卡片事件的動作 |
| 揭示 | 將已抽出的卡片正式公開，並允許該卡片進入結算階段的狀態 |
| 結算 | 依卡片正式規則套用選擇、效果、財務處理與後續事件的階段 |
| 完成 | 卡片事件所有正式效果都已成立，且已達可離開卡片系統的狀態 |
| 後續卡 | 因正式規則而在主要卡片之後繼續建立的正式卡片事件 |
| 家庭卡 | 具有家庭歷程共同參與規則的正式卡片事件 |
| 卡片所有權 | 哪一位玩家擁有某一張卡片事件的操作權與回覆責任 |
| 卡片事件 | 以卡片為主體的正式事件，必須遵循抽牌、揭示、結算、完成的正式生命周期 |

# State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待建立 | 表示卡片入口已成立但尚未抽牌 | 正式抽牌入口被觸發 | 抽出卡片並建立卡片事件 | 確認牌堆類型、建立事件所有權 | 直接套用效果 |
| 已抽牌 | 表示卡片已自有效牌堆取出 | 完成抽牌 | 進入揭示 | 指定目前卡片、移出有效牌堆 | 直接完成、直接棄置 |
| 已揭示 | 表示卡片已正式公開 | 抽牌完成且執行揭示 | 進入結算 | 顯示正式卡面、允許開始結算 | 在揭示前生效的任何效果 |
| 結算中 | 表示正在套用卡片正式規則 | 已揭示且開始處理規則 | 效果全部成立後進入完成 | 選擇、支付、獲得、建立後續卡、建立共同參與 | 提前切換下一事件 |
| 等待共同參與 | 表示家庭卡正在等待其他玩家回覆 | 家庭卡揭示後建立共同參與流程 | 所有符合資格玩家皆完成回覆 | 接收參與、失敗、拒絕的正式結果 | 略過未回覆玩家直接完成 |
| 等待財務檢核 | 表示卡片效果已進入正式金額結算 | 結算涉及正式交易 | 財務檢核完成 | 進行財務檢核 | 在財務檢核前宣告交易成立 |
| 已完成 | 表示卡片所有正式效果已成立 | 結算、共同參與與財務處理全部完成 | 棄置並離開目前事件 | 記錄正式結果、進入棄置 | 新增新的本卡片效果 |
| 已棄置 | 表示卡片已回到已用牌堆 | 已完成且卡片離開目前事件 | 後續新一張事件開始 | 進入已用牌堆、等待未來重洗 | 再次作為當前卡片操作 |

# Rules

## 卡片類別規則

1. 正式卡片只分為幸福卡、機運卡與新聞卡三大牌堆類別。
2. 後續卡是正式卡片事件地位，不是第四個牌堆。
3. 家庭卡是幸福卡中的正式事件子類型，不是獨立牌堆。
4. 市場行情效果屬新聞卡的正式子類型，仍由卡片系統負責其揭示與結算入口。

## 牌堆規則

1. 每一個牌堆都必須維持有效牌堆與已用牌堆兩個正式集合。
2. 抽牌只能從有效牌堆抽取。
3. 卡片完成後必須進入已用牌堆，作為正式棄置結果。
4. 已用牌堆中的卡片不得在同一輪未重洗前再次被抽到。
5. 只有當有效牌堆抽完時，才可把已用牌堆重新洗回有效牌堆。

## 抽牌規則

1. 抽牌只能由正式卡片入口觸發。
2. 抽牌完成後，卡片必須先建立為正式卡片事件。
3. 抽牌本身不代表效果成立。
4. 每一張被抽出的卡片都必須有唯一事件擁有者。

## 揭示規則

1. 所有卡片都必須先揭示，才可進入結算。
2. 揭示前不得生效任何正式卡片效果。
3. 市場行情相關卡片也必須在揭示後才可正式生效。
4. 家庭卡的共同參與流程只能在源卡揭示後開啟。

## 結算規則

1. 卡片結算必須依正式卡面規則處理。
2. 涉及支付、收入、資產、負債、月支出、幸福值或共同參與的效果，都屬於卡片結算的一部分。
3. 涉及正式交易的卡片效果，必須先完成財務檢核，交易才正式成立。
4. 卡片產生的後續卡，必須作為新的正式卡片事件處理。
5. 在卡片正式完成前，不得視為事件已結束。

## 棄置規則

1. 卡片只有在正式完成後才可棄置。
2. 棄置的正式結果，是將卡片移入該牌堆的已用牌堆。
3. 未完成的卡片不得提前棄置。
4. 後續卡與家庭卡完成後，同樣必須依所屬牌堆進入已用牌堆。

## 後續卡規則

1. 後續卡是正式卡片事件。
2. 後續卡必須遵循與一般卡片相同的正式生命周期。
3. 後續卡未完成前，來源卡片所屬的事件鏈不得視為全部結束。
4. 後續卡不得以略過抽牌、略過揭示或直接生效的方式成立。

## 家庭卡規則

1. 家庭卡屬於正式多人卡片事件。
2. 符合資格的共同參與玩家，都必須完成自己的正式回覆。
3. 正式回覆結果只包含參與成功、參與失敗、拒絕參與。
4. 所有符合資格玩家都完成回覆後，家庭卡事件才可完成。
5. 家庭卡的個人後續效果，仍需回到正式卡片或正式事件流程承接。

## 所有權規則

1. 一般卡片只有卡片事件擁有者可操作。
2. 家庭卡的共同參與玩家，只能操作屬於自己回覆責任的部分。
3. 影響全體玩家的卡片，不代表全體玩家都擁有操作權。
4. 卡片所有權是正式規則，不得由下游文件重新定義。

## 完成規則

1. 卡片事件完成，必須以揭示、結算、共同參與與財務處理都已完成為準。
2. 卡片事件完成後，才可離開當前卡片事件並進入棄置。
3. 卡片事件全部完成前，回合不得切換至下一位玩家。
4. 卡片事件完成門檻由本文件定義，回合切換責任由 `TURN_SYSTEM.md` 承接。

# Flow

```text
正式卡片入口成立
  ->
建立卡片事件
  ->
從對應牌堆抽牌
  ->
卡片進入已抽牌
  ->
正式揭示
  ->
進入結算
  ->
若需共同參與
  ->
等待所有符合資格玩家回覆
  ->
若需財務檢核
  ->
完成財務檢核
  ->
若產生後續卡
  ->
建立後續卡事件
  ->
原卡片完成
  ->
卡片棄置至已用牌堆
  ->
若仍有後續卡
  ->
後續卡重複相同流程
  ->
全部卡片事件完成
```

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待建立 | 建立卡片事件 | 正式卡片入口成立 | 待建立 -> 已抽牌 | 待建立 -> 已完成 |
| 已抽牌 | 進入揭示 | 自有效牌堆抽出卡片 | 已抽牌 -> 已揭示 | 已抽牌 -> 結算中、已完成 |
| 已揭示 | 開始結算 | 卡片正式公開 | 已揭示 -> 結算中 | 已揭示 -> 已棄置 |
| 結算中 | 進入等待共同參與 | 家庭卡需要多人回覆 | 結算中 -> 等待共同參與 | 結算中 -> 已棄置 |
| 結算中 | 進入等待財務檢核 | 卡片效果涉及正式交易 | 結算中 -> 等待財務檢核 | 結算中 -> 已棄置 |
| 結算中 | 完成 | 無共同參與且無財務檢核待處理 | 結算中 -> 已完成 | 結算中 -> 待建立 |
| 等待共同參與 | 返回結算中 | 所有符合資格玩家皆已回覆 | 等待共同參與 -> 結算中 | 等待共同參與 -> 已棄置 |
| 等待財務檢核 | 返回結算中 | 財務檢核正式完成 | 等待財務檢核 -> 結算中 | 等待財務檢核 -> 已棄置 |
| 已完成 | 棄置 | 所有正式效果成立 | 已完成 -> 已棄置 | 已完成 -> 已揭示 |
| 已棄置 | 結束當前事件 | 已進入已用牌堆 | 已棄置 -> 待建立 | 已棄置 -> 結算中 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 有效牌堆已空 | 無法繼續抽牌 | 先將已用牌堆重洗回有效牌堆，再進行抽牌 |
| 卡片已抽出但尚未揭示 | 可能被誤認為已生效 | 視為未完成事件，不得套用任何效果 |
| 家庭卡沒有其他符合資格玩家 | 共同參與流程是否成立 | 不建立等待共同參與，直接處理事件擁有者的正式流程 |
| 家庭卡仍有玩家未回覆 | 事件可能被提前結束 | 事件必須維持在等待共同參與，不得完成 |
| 卡片產生後續卡 | 來源卡是否可直接結束 | 來源卡須先完成自身效果，後續卡再作為正式事件繼續處理 |
| 卡片效果涉及支付但現金不足 | 是否可直接失敗略過 | 必須轉入正式財務檢核與正式負債處理規則 |
| 同一回合連續產生多張卡片 | 事件順序可能混亂 | 必須依正式事件順序逐一完成，不得跳過未完成卡片 |
| 全體影響卡片 | 非擁有者可能誤操作 | 只有擁有者操作主卡事件，其他玩家只承接自己被影響的正式結果 |
| 卡片完成後重新抽到相同卡 | 可能違反抽完重洗原則 | 只有在原牌堆有效牌堆耗盡並完成重洗後，才可再次抽到 |

# Design Principles

## 單一職責（Single Responsibility）

- 本文件只負責卡片系統
- 不承擔回合、棋盤、財務、幸福總分或市場估值的主責定義

## 模組化（Modular Design）

- 卡片類別、牌堆規則、生命周期與所有權集中在本文件
- 跨系統效果只描述交界，不複製下游細節

## 低耦合（Low Coupling）

- 本文件只依賴必要上游文件
- 不向下覆蓋幸福、家庭、市場、企業或財務的專屬責任

## 高內聚（High Cohesion）

- 本文件所有章節都圍繞卡片事件如何被建立、處理、完成與棄置

## 單一權威來源（Single Source of Truth）

- 卡片生命周期以本文件為唯一正式來源
- 家庭卡的卡片層責任以本文件為唯一正式來源

## 不可循環依賴（No Circular Dependency）

- 本文件只依賴上游核心 GDD
- 下游系統若需卡片規則，應引用本文件，不得反向讓本文件依賴其細部設計

## 依賴方向固定（Top-down Dependency）

- 依賴方向維持為 Product Specification -> Decision -> Core GDD -> Domain GDD

## 資料與 UI 分離

- 本文件只定義正式卡片資料模型，不描述畫面、互動元件或顯示樣式

## 規則與實作分離

- 本文件只定義卡片正式規則與正式狀態，不描述技術實作方式

## 產品規則不得寫進程式

- 卡片正式玩法必須先定義在 Product Specification、Decision 與本文件中，再由實作承接

# Writing Rules

1. 本文件不得重新定義產品規則。
2. 本文件不得包含 `Option`、`Recommendation`、`Problem`、`Current Implementation`、`Need Confirmation`、`TODO`、`Legacy`、`RFC Analysis`。
3. 本文件不得描述程式碼。
4. 本文件不得描述 Framework。
5. 本文件不得描述 UI 細節。
6. 本文件不得描述 API。
7. 本文件不得描述 Database。
8. 本文件不得重新開啟產品討論。
9. 已由 `docs/spec/PRODUCT_SPECIFICATION.md` 定義的卡片玩法，必須直接引用。
10. 已由 Confirmed Decision 定義的卡片生命周期與事件地位，必須直接承接。
11. 本文件不得與其他 GDD 重複定義責任。
12. 若責任跨模組，必須引用其他 GDD，而不是複製其內容。

# Modular Design Rules

- 一個 GDD 只負責一個系統，本文件只負責卡片系統。
- 本文件可依賴多份上游 GDD，但不得反向依賴下游細部系統。
- 本文件不得與其他 GDD 形成循環依賴。
- 卡片正式生命周期只能在本文件定義一次。
- 家庭卡在卡片層的責任只能在本文件定義一次，家庭系統只能承接多人互動細部設計。
- 後續卡的正式地位只能在本文件與 `EVENT_SYSTEM.md` 的交界中定義，不得由下游文件重寫。
- 所有下游 GDD 若需使用卡片規則，必須引用本文件，而不是複製卡片流程。
