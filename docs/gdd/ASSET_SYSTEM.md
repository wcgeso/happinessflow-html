## Purpose

本文件定義資產系統的正式設計，負責說明資產類別、所有權、購買、出售、估值、附掛狀態與升級規則。

本文件只承接已確認的產品規則與決策，不重新定義產品規則。

資產系統的正式規則來源如下：

- 產品規則以 `docs/spec/PRODUCT_SPECIFICATION.md` 為準
- 已確認的資產、財務、銀行與狀態決策，以相關 Decision 文件為準

## Scope

### 本文件負責

- 定義正式資產類別
- 定義資產所有權與附掛關係
- 定義資產購買、出售與升級規則
- 定義資產估值規則
- 定義保險附掛與貸款附掛規則

### 本文件不負責

- 定義銀行事件與銀行服務窗口流程
- 定義正式財務檢核流程
- 定義卡片事件與棋盤事件流程
- 定義保險理賠規則
- 定義房屋市場與企業市場的完整子系統規格

### 邊界原則

- 資產系統只定義資產本體與其附掛狀態
- 銀行進入條件由 `BANK_SYSTEM.md` 負責
- 財務成立條件由 `FINANCIAL_SYSTEM.md` 負責
- 房屋、企業、保險、貸款的子領域規則由下游 GDD 擴充，不在本文件重複定義

## Definitions

| 名詞 | 定義 |
|---|---|
| 資產 | 玩家可持有、可估值、可交易或可附掛狀態的正式財務項目 |
| 資產類別 | 用於區分股票、定存、房屋、企業與汽車的正式分類 |
| 所有權 | 用於判定某項資產正式屬於哪位玩家的規則 |
| 購買 | 玩家取得資產所有權並完成正式交易的行為 |
| 出售 | 玩家移除資產所有權並完成正式交易的行為 |
| 估值 | 用於計算資產正式價值的規則 |
| 附掛狀態 | 綁定在資產上的保險、自用、升級或貸款關聯狀態 |
| 升級 | 改變資產等級、效果或現金流的正式變更 |
| 保險附掛 | 將保險狀態正式綁定在醫療、房屋或汽車相關資產上的規則 |
| 貸款附掛 | 將資產相關負債正式關聯至對應資產的規則 |
| 正式來源 | 同一項正式規則或正式資料唯一承認的權威來源 |

## Data Model

| 欄位名稱 | 型別 | 用途 | 限制 | 說明 |
|---|---|---|---|---|
| assets | 資產清單 | 保存玩家正式持有的全部資產 | 不得拆成第二份正式所有權清單 | 為玩家資產所有權的正式來源 |
| assetId | 字串 | 識別單一資產 | 同一玩家內不得重複 | 用於綁定出售、升級、保險與貸款關係 |
| assetType | 列舉 | 區分資產類別 | 僅限股票、定存、房屋、企業、汽車 | 不得使用非正式類別取代正式分類 |
| ownerId | 字串 | 標示資產持有人 | 必須對應唯一玩家 | 用於所有權判定 |
| quantity | 數值 | 表示持有數量 | 僅適用可分量資產 | 例如股票張數或保單數量 |
| purchaseValue | 數值 | 保存購買時的正式交易值 | 必須來自正式交易結果 | 用於交易紀錄與資產追蹤 |
| currentValue | 數值 | 表示目前正式估值 | 必須依估值規則計算 | 不得由非正式副本覆蓋 |
| incomeEffect | 數值 | 表示資產對收入的影響 | 僅於適用資產使用 | 例如定存利息或企業現金流 |
| expenseEffect | 數值 | 表示資產對支出的影響 | 僅於適用資產使用 | 例如保險支出或汽車相關支出 |
| insuranceStatus | 狀態 | 表示資產是否附掛保險 | 不得脫離資產獨立存在 | 適用房屋與汽車資產 |
| selfUseStatus | 狀態 | 表示房屋是否自用 | 僅適用房屋 | 用於區分自住與出租 |
| upgradeStatus | 狀態 | 表示資產是否已升級 | 僅適用可升級資產 | 適用企業或其他可升級資產 |
| linkedLiabilityId | 字串 | 連結對應負債 | 僅適用有貸款的資產 | 用於正式貸款附掛關係 |
| marketValueSource | 列舉 | 標示估值來源 | 必須引用正式權威 | 用於界定市場價格依據 |
| status | 列舉 | 表示資產生命週期狀態 | 僅限正式狀態 | 例如持有中、出售中、已出售 |

## State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 未持有 | 表示玩家尚未擁有該資產 | 玩家尚未完成購買，或已完成出售 | 完成正式購買 | 查看購買條件 | 不得出售、升級或附掛資產專屬狀態 |
| 購買中 | 表示資產購買正在進行正式交易 | 玩家發起資產購買且已進入正式交易流程 | 購買完成或購買取消 | 檢查購買限制、確認正式交易 | 不得視為已持有 |
| 持有中 | 表示玩家正式擁有該資產 | 購買完成，或交易後仍保留所有權 | 發起出售、完成出售、失去所有權 | 出售、升級、依規則附掛狀態 | 不得重複建立第二份所有權 |
| 升級中 | 表示資產升級正在進行 | 已持有且發起升級流程 | 升級完成或升級取消 | 確認升級成本與升級結果 | 不得略過正式交易成立條件 |
| 出售中 | 表示資產出售正在進行正式交易 | 已持有且發起出售流程 | 出售完成或出售取消 | 結清出售結果與相關附掛狀態 | 不得同時再次購買相同唯一資產 |
| 已出售 | 表示該資產已完成出售 | 出售完成且所有權移除 | 重新購買新資產 | 保留正式交易紀錄 | 不得再被視為持有中資產 |

## Rules

### 資產類別規則

- 本文件主責的正式資產主體共有五種：
  - 股票
  - 定存
  - 房屋
  - 企業
  - 汽車
- 保險屬於資產規則範圍內的正式狀態，但在本文件中一律以附掛狀態處理，不作為獨立資產實體。
- 非正式名稱不得取代正式資產類別。

### 所有權規則

- 玩家資產所有權以 `assets` 為唯一正式來源。
- 不得為同一資產建立第二份正式所有權狀態。
- 資產上的保險、自用、升級與貸款關聯，必須綁定在對應資產上。
- 多人同步副本不得取代正式資產所有權。

### 購買規則

- 所有資產購買都必須在正式交易成立後才算完成。
- 股票與汽車屬於可隨時購買的資產。
- 定存的辦理必須符合銀行服務窗口規則。
- 房屋與企業的購買，必須依其上游事件或交易入口規則進入正式交易。
- 汽車再次購買前，必須先完成現有汽車的出售。

### 出售規則

- 所有資產出售都必須完成正式交易後才算完成。
- 股票出售以持有數量與正式市場價格計算。
- 定存解約視為資產出售的一種，且不受銀行服務窗口限制。
- 房屋、企業與汽車出售後，必須同步移除其資產所有權與附掛狀態。
- 若出售資產時存在對應貸款，必須一併依貸款規則處理。

### 估值規則

- 股票估值必須使用正式市場價格來源。
- 房屋與企業若需要市場估值，必須使用正式市場資料結構。
- 資產估值只能使用正式來源，不得由同步副本或非正式欄位取代。
- 購買價格可作為交易紀錄的一部分，但不得直接取代正式目前估值。

### 升級規則

- 僅可升級的資產才允許進入升級流程。
- 升級完成後，必須同步更新該資產的正式狀態與效果。
- 企業升級後，必須同步更新其現金流影響。
- 升級若涉及成本或價值變化，必須依正式交易規則成立。

### 保險附掛規則

- 醫療保險以保險狀態或數量表示。
- 房屋保險必須附掛於對應房屋資產。
- 汽車保險必須附掛於對應汽車資產。
- 保險購買完成後，產生的每月支出自下一次月結算起生效。
- 保險理賠規則不由本文件定義，應由保險系統文件承接。

### 貸款附掛規則

- 資產相關貸款必須透過正式負債資料與資產建立關聯。
- 房屋貸款、企業貸款與汽車貸款都屬於資產附掛貸款。
- 貸款附掛不得脫離資產語意獨立描述為另一份所有權。
- 出售資產時，若存在附掛貸款，必須同步處理該貸款的結算關係。

### 正式來源規則

- 股票價格的正式來源必須是正式市場價格權威。
- 負債的正式來源必須是正式負債資料。
- 舊名稱、舊欄位或同步副本不得作為正式規則來源。

## Flow

```text
開始
  ->
確認資產類別
  ->
確認是否符合購買、出售或升級條件
  ->
進入正式交易流程
  ->
完成所有權或附掛狀態變更
  ->
更新正式估值與正式效果
  ->
完成
```

## State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 未持有 | 發起購買 | 玩家符合取得條件 | 未持有 -> 購買中 | 未持有 -> 升級中、未持有 -> 出售中 |
| 購買中 | 購買成立 | 正式交易完成 | 購買中 -> 持有中 | 購買中 -> 已出售 |
| 購買中 | 購買取消 | 交易未成立或被取消 | 購買中 -> 未持有 | 購買中 -> 升級中 |
| 持有中 | 發起升級 | 符合升級條件 | 持有中 -> 升級中 | 持有中 -> 未持有 |
| 持有中 | 發起出售 | 玩家決定移轉所有權 | 持有中 -> 出售中 | 持有中 -> 購買中 |
| 升級中 | 升級完成 | 升級正式成立 | 升級中 -> 持有中 | 升級中 -> 已出售 |
| 升級中 | 升級取消 | 升級未成立 | 升級中 -> 持有中 | 升級中 -> 未持有 |
| 出售中 | 出售完成 | 正式交易完成 | 出售中 -> 已出售 | 出售中 -> 升級中 |
| 出售中 | 出售取消 | 交易未成立或被取消 | 出售中 -> 持有中 | 出售中 -> 未持有 |
| 已出售 | 重新取得 | 新一輪購買成立 | 已出售 -> 持有中 | 已出售 -> 升級中、已出售 -> 出售中 |

## Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 玩家已持有汽車時再次購買汽車 | 唯一持有規則可能被破壞 | 必須先完成現有汽車出售，才可購買新汽車 |
| 資產出售時仍有附掛貸款 | 所有權移除與貸款結算可能脫鉤 | 出售流程必須同步處理對應貸款 |
| 房屋在自住與出租間切換 | 房屋狀態與效果可能不同步 | 必須同步更新房屋正式狀態與其效果 |
| 資產出售時仍附掛保險 | 附掛狀態可能殘留 | 出售完成時必須同步終止或移除對應附掛狀態 |
| 市場估值來源不一致 | 資產價值可能出現多種版本 | 一律以正式權威來源為準 |
| 定存解約發生在非回合時段 | 可能與銀行服務窗口混淆 | 定存解約屬正式允許項目，可依正式交易規則完成 |
| 購買或出售在遊戲結束後觸發 | 正式規則已不允許新交易 | 遊戲結束後不得再建立新的資產交易 |

## Design Principles

### 單一職責（Single Responsibility）

- 本文件只負責資產系統
- 本文件不承擔銀行、卡片、事件或多人同步主責

### 模組化（Modular Design）

- 資產類別、所有權、估值與附掛狀態由本文件統一定義
- 子領域規則由下游 GDD 擴充，不在本文件複製

### 低耦合（Low Coupling）

- 本文件只依賴銀行、財務與已確認決策中的必要規則
- 不跨寫其他系統的主責內容

### 高內聚（High Cohesion）

- 本文件所有章節都圍繞資產本體、附掛狀態與生命週期

### 單一權威來源（Single Source of Truth）

- 資產所有權、正式價格與正式負債都必須有唯一正式來源

### 不可循環依賴（No Circular Dependency）

- 本文件只依賴上游文件
- 不反向依賴下游子系統 GDD

### 依賴方向固定（Top-down Dependency）

- 本文件依賴 Product Specification、Decision、`BANK_SYSTEM.md` 與 `FINANCIAL_SYSTEM.md`
- 下游 GDD 應依賴本文件，不得反向覆蓋本文件責任

### 資料與 UI 分離

- 本文件只定義正式資料模型與正式規則
- 不描述任何畫面或操作呈現細節

### 規則與實作分離

- 本文件只描述正式設計
- 不描述任何實作方式

### 產品規則不得寫進程式

- 本文件承接正式產品規格與已確認決策
- 實作必須追隨本文件，不得取代本文件

## Writing Rules

1. 本文件不得重新定義產品規則。
2. 本文件不得包含：
   - Option
   - Recommendation
   - Problem
   - Current Implementation
   - Need Confirmation
   - TODO
   - RFC Analysis
   - Legacy Analysis
3. 本文件不得描述程式碼。
4. 本文件不得描述 Framework。
5. 本文件不得描述 UI 細節。
6. 本文件不得描述 API。
7. 本文件不得描述 Database。
8. 本文件不得重新開啟產品討論。
9. 本文件若引用產品規則，必須直接以上游正式文件為準。
10. 本文件若引用已確認決策，必須直接承接，不得改寫其結論。
11. 本文件不得與其他 GDD 重複定義責任。
12. 本文件若需要跨模組規則，必須以引用方式處理。

## Modular Design Rules

- 一個 GDD 只負責一個系統，本文件只負責資產系統。
- 本文件可依賴多份上游 GDD，但不得反向依賴下游 GDD。
- 本文件不得與其他 GDD 形成循環依賴。
- 每個正式資產規則只能定義一次。
- 所有下游 GDD 必須引用本文件中的資產正式定義，而不是複製內容。
