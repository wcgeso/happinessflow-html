## Purpose

本文件定義《第二人生》的人生夢想系統正式設計，負責說明人生夢想的建立、完成條件、夢想與幸福值的關聯、夢想評分與夢想里程碑。

本文件不得重新定義產品規則。

人生夢想、幸福值達標、財務自由與遊戲結束條件的正式邊界，皆以 Product Specification 與已確認 Decision 為準。

## Scope

### 本文件負責

- 定義人生夢想的正式責任範圍
- 定義人生夢想的正式資料模型
- 定義人生夢想的正式狀態
- 定義人生夢想的完成條件
- 定義人生夢想與幸福值的正式關聯
- 定義人生夢想評分
- 定義人生夢想里程碑規則

### 本文件不負責

- 重新定義幸福值的來源與主要計分規則
- 重新定義遊戲勝利條件
- 重新定義財務自由條件
- 重新定義回合、事件、卡片、銀行或資產規則
- 描述任何畫面、介面或操作元件

### 邊界原則

- 人生夢想只定義夢想本體、完成判定與里程碑意義
- 幸福值的主要評分地位不由本文件改寫
- 若夢想完成會引發幸福值變動，該變動必須交由幸福系統承接

## Definitions

本章節用於定義本系統的核心名詞。

所有名詞都必須具有唯一正式定義。

| 名詞 | 定義 |
|---|---|
| 人生夢想 | 每位玩家可建立的正式人生目標；完成後屬於重要里程碑，但不會直接結束遊戲。 |
| 夢想完成條件 | 判定人生夢想是否成立的一組正式要求；必須全部滿足才可視為完成。 |
| 夢想狀態 | 人生夢想目前所處的正式生命週期階段。 |
| 夢想評分 | 用於記錄人生夢想完成成果的附屬評分；不得取代幸福值作為主要評分依據。 |
| 夢想里程碑 | 人生夢想正式完成後所形成的里程碑狀態；不等於遊戲結束。 |
| 幸福值 | 遊戲中的主要評分依據；本文件只承接其與人生夢想的關聯，不重新定義其來源與公式。 |

## Data Model

本章節描述人生夢想系統的正式資料模型。

| 欄位名稱 | 型別 | 用途 | 限制 | 說明 |
|---|---|---|---|---|
| dreamId | 文字 | 識別單一人生夢想 | 同一玩家同一時間不得重複 | 作為人生夢想的正式識別值 |
| ownerId | 玩家識別碼 | 標示夢想擁有者 | 必須對應唯一玩家 | 用於判定夢想屬於哪位玩家 |
| dreamTitle | 文字 | 表示人生夢想名稱 | 不得為空 | 用於正式呈現夢想主題 |
| dreamStatus | 列舉 | 表示人生夢想目前狀態 | 僅限本文件定義的正式狀態 | 用於判定夢想是否已完成或已鎖定 |
| completionCriteria | 條件集合 | 表示夢想完成條件 | 必須可驗證 | 完成時必須全部成立 |
| dreamScore | 數值 | 表示人生夢想的完成成果分數 | 只能反映正式完成成果 | 只作輔助評分，不得取代幸福值 |
| happinessDelta | 數值 | 表示人生夢想完成後對幸福值的正式關聯變化 | 必須由幸福系統承接 | 若該夢想不影響幸福值，則為 0 |
| completedAt | 時間戳 | 表示夢想正式完成的時間 | 僅於已完成時有效 | 用於追蹤完成先後與里程碑登錄 |

## State

本章節定義本系統的正式 State。

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 未設定 | 表示玩家尚未建立正式人生夢想 | 玩家尚未建立夢想 | 夢想正式建立後離開 | 建立夢想、設定完成條件 | 視為已完成、計入夢想評分 |
| 進行中 | 表示人生夢想已建立但尚未完成 | 夢想已正式建立且完成條件未全滿足 | 完成條件全數成立，或遊戲正式結束 | 追蹤進度、檢查條件、更新夢想評分 | 宣稱夢想已完成、宣稱遊戲已結束 |
| 已完成 | 表示人生夢想已正式完成 | 完成條件全數成立 | 遊戲正式結束後離開至結束鎖定 | 登錄里程碑、記錄夢想評分、承接幸福值關聯 | 重新回到進行中、取消完成結果 |
| 結束鎖定 | 表示遊戲正式結束後的鎖定狀態 | 遊戲正式結束 | 無 | 讀取既有夢想結果 | 任何新的夢想變更、重新評分、重新判定完成 |

## Rules

### 1. 人生夢想建立規則

1. 每位玩家都可以有人生夢想。
2. 人生夢想必須在正式建立後，才可開始累積進度或進行完成判定。
3. 同一個人生夢想的正式內容必須能被唯一識別與追蹤。
4. 人生夢想的正式內容不得與遊戲結束條件混為一談。

### 2. 完成條件規則

1. 人生夢想的完成條件必須由正式條目明確定義。
2. 完成判定必須以全部條件都成立為準，任一條件未完成都不得視為完成。
3. 若人生夢想的完成條件涉及金額、資產、負債、收入或支出，必須先符合財務系統的正式規則。
4. 若人生夢想的完成條件涉及其他正式系統，該系統的正式完成條件必須先成立。

### 3. 夢想與幸福值規則

1. 幸福值是遊戲的主要評分依據。
2. 本文件只定義人生夢想與幸福值的正式關聯，不重新定義幸福值本身的主要來源。
3. 若人生夢想完成會產生幸福值變化，該變化必須由幸福系統承接。
4. 人生夢想完成不得以幸福值門檻反推完成，除非該夢想的正式條件已明確寫入。
5. 幸福值達標是人生里程碑，但不會因本文件而變成遊戲結束條件。

### 4. 夢想評分規則

1. 夢想評分用於記錄人生夢想完成成果。
2. 夢想評分只能作為附屬評分，不得取代幸福值作為主要評分依據。
3. 夢想評分應反映完成條件的達成品質、附加條件的完成情形與正式完成結果。
4. 若某人生夢想沒有額外評分條件，夢想評分仍需保留為可追蹤的正式結果。
5. 夢想評分不得單獨改寫遊戲勝負。

### 5. 夢想里程碑規則

1. 人生夢想完成時，屬於重要里程碑。
2. 人生夢想完成不會直接結束遊戲。
3. 人生夢想完成後，玩家仍須繼續進行遊戲，直到正式結束條件成立。
4. 人生夢想完成後，必須保留正式完成紀錄與夢想評分結果。

### 6. 遊戲結束規則

1. 遊戲正式結束後，人生夢想狀態進入結束鎖定。
2. 遊戲正式結束後，不得再建立新的夢想進度或重新計分。
3. 遊戲結束時，以幸福值高低決定勝負。
4. 若人生夢想與幸福值相關，仍以幸福值作為主要評分依據。

## Flow

```text
開始
  ->
建立人生夢想
  ->
設定完成條件
  ->
追蹤夢想進度
  ->
檢查完成條件
  ->
條件未全數成立
  ->
維持進行中
  ->
條件全數成立
  ->
計算夢想評分
  ->
承接幸福值關聯
  ->
登錄夢想里程碑
  ->
等待遊戲正式結束
  ->
結束鎖定
  ->
完成
```

## State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 未設定 | 進入進行中 | 玩家正式建立人生夢想 | 未設定 -> 進行中 | 未設定 -> 已完成 |
| 進行中 | 進入已完成 | 完成條件全數成立 | 進行中 -> 已完成 | 進行中 -> 未設定 |
| 進行中 | 進入結束鎖定 | 遊戲正式結束 | 進行中 -> 結束鎖定 | 進行中 -> 未設定 |
| 已完成 | 進入結束鎖定 | 遊戲正式結束 | 已完成 -> 結束鎖定 | 已完成 -> 進行中 |
| 未設定 | 進入結束鎖定 | 遊戲正式結束且未建立夢想 | 未設定 -> 結束鎖定 | 未設定 -> 已完成 |
| 結束鎖定 | 無 | 遊戲已正式結束 | 無 | 結束鎖定 -> 進行中、結束鎖定 -> 已完成 |

## Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 夢想完成條件同時包含財務與非財務要求 | 可能只完成部分條件就誤判完成 | 必須等待所有條件都成立，才可正式完成。 |
| 夢想完成當下同時觸發幸福值變動 | 完成與幸福值更新順序可能混淆 | 先判定夢想已完成，再由幸福系統處理幸福值關聯結果。 |
| 幸福值已達 100，但人生夢想尚未完成 | 里程碑可能被誤當成結束 | 仍視為進行中，人生夢想未完成前不得標記為已完成。 |
| 人生夢想已完成，但遊戲尚未結束 | 可能誤以為後續流程可停止 | 夢想只是一個里程碑，遊戲仍須繼續到正式結束。 |
| 多個玩家在同一時間完成人生夢想 | 里程碑登錄可能互相干擾 | 各玩家的夢想紀錄彼此獨立處理。 |
| 遊戲正式結束時夢想尚未完成 | 是否仍可繼續變更 | 不可。進入結束鎖定後，夢想狀態不得再變更。 |
| 夢想條件與上游正式規則衝突 | 可能出現無法成立的完成條件 | 以 Product Specification 與已確認 Decision 為準，衝突條件不得作為正式完成條件。 |

## Design Principles

- 單一職責：本文件只定義人生夢想本體、完成條件、夢想評分與夢想里程碑。
- 模組化：涉及幸福值與財務門檻的規則一律引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔回合、事件、銀行、資產或卡片的正式責任。
- 高內聚：所有夢想建立、進度、完成與封存規則集中於本文件。
- 單一權威來源：人生夢想的正式產品規則以 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件可依賴幸福與財務系統，但不得反向要求它們依賴本文件。
- 依賴方向固定：夢想系統承接上游結果，不重寫上游評分與結算規則。
- 資料與 UI 分離：本文件只描述正式夢想資料與規則，不描述任何呈現方式。
- 規則與實作分離：本文件不描述技術流程或執行細節。
- 產品規則不得寫進程式：夢想規則調整必須先更新正式規格。

## Writing Rules

- 不得重新定義幸福值為主要評分依據的產品規則。
- 不得把財務自由或幸福值達標改寫為人生夢想完成條件，除非上游正式規格明確定義。
- 不得包含現況分析、問題盤點、選項比較、建議段落、待確認事項或待辦項目。
- 不得描述程式、框架、介面協定、資料庫或畫面細節。
- 若人生夢想牽涉其他系統效果，必須以引用方式承接，不得在本文件複製其他系統規則。

## Modular Design Rules

- 本文件只負責夢想系統，不承擔幸福、財務、回合、事件或資產系統責任。
- 本文件可依賴 `docs/gdd/FINANCIAL_SYSTEM.md` 與 `docs/gdd/HAPPINESS_SYSTEM.md`，不得反向依賴下游文件。
- 其他 GDD 若需要引用夢想完成條件或夢想里程碑，必須以本文件為正式來源。
- 本文件與其他 GDD 的依賴方向必須維持 DAG，不得形成循環依賴。
- 人生夢想規則只能在本文件定義一次，其他文件不得複製或改寫。
