# Purpose

本文件定義《幸福流》的企業系統正式設計。

本文件只負責企業、收購、升級、現金流、企業貸款、企業市場與企業狀態機的正式規則與正式資料模型。

本文件不得重新定義產品規則。

所有企業相關正式規則都必須以 `docs/spec/PRODUCT_SPECIFICATION.md`、已確認 Decision、Core GDD 與既有 Domain GDD 為正式來源。

# Scope

## 本文件負責

- 定義企業的正式責任範圍
- 定義企業收購的正式條件與結果
- 定義企業升級的正式條件與結果
- 定義企業現金流的正式來源與結算邊界
- 定義企業貸款的正式附掛關係
- 定義企業市場的正式引用邊界
- 定義企業系統的正式資料模型、狀態與狀態機

## 本文件不負責

- 重新定義資產所有權的正式權威
- 重新定義財務檢核的正式成立條件
- 重新定義貸款系統的借款、還款與自動償還規則
- 重新定義市場系統的行情更新、揭示與生效規則
- 重新定義卡片抽取、揭示與結算流程
- 描述任何程式、介面或技術實作

## 邊界原則

- 企業系統只負責企業本體、企業收購、企業升級、企業現金流與企業貸款的正式語意。
- 企業所有權由 `ASSET_SYSTEM.md` 承接，企業交易成立由 `FINANCIAL_SYSTEM.md` 承接。
- 企業貸款的附掛與清償關係由 `LOAN_SYSTEM.md` 承接。
- 企業市場的正式價格與行情來源由 `MARKET_SYSTEM.md` 承接。
- 若企業效果來自卡片或正式事件，卡片與事件的生命週期由 `CARD_SYSTEM.md` 與其上游 GDD 承接，本文件只承接企業結果。

# Definitions

| 名詞 | 定義 |
|---|---|
| 企業 | 玩家可持有、可收購、可升級、可處分，且可產生正式現金流的正式資產主體。 |
| 收購 | 取得企業正式所有權的交易行為；其正式成立必須通過財務檢核與資產所有權成立條件。 |
| 升級 | 改變企業等級、現金流、貸款影響或其他正式企業效果的正式變更。 |
| 現金流 | 企業在正式結算中對玩家現金所產生的淨影響，可為收入或支出。 |
| 企業貸款 | 與企業正式附掛的負債；其成立、還款與清償皆屬正式貸款規則的一部分。 |
| 企業市場 | 企業標的的正式市場資訊集合，用於價格、來源與生效狀態判定。 |
| 企業狀態 | 企業在收購、營運、升級、處分與終止之間的正式生命週期階段。 |
| 企業狀態機 | 描述企業從待收購到已處分的正式轉換模型。 |
| 企業交易紀錄 | 保存企業收購、升級、處分與貸款影響的正式結果紀錄。 |
| 企業市場標的 | 可供引用的單一企業市場對象；其價格與狀態由市場系統提供正式來源。 |

# State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待收購 | 表示企業尚未被玩家正式持有 | 企業市場標的已成立，但尚未完成收購 | 完成正式收購後離開 | 檢查來源、準備收購、引用市場價格 | 直接套用營運結果、直接升級 |
| 收購中 | 表示企業收購正在正式處理 | 玩家已提出收購且進入正式交易流程 | 收購正式成立或失敗後離開 | 財務檢核、建立所有權、建立交易紀錄 | 在收購完成前宣告營運中 |
| 營運中 | 表示企業已正式持有並可產生現金流 | 收購正式成立後進入 | 進入升級中或處分中後離開 | 計入現金流、引用市場價格、處理貸款影響 | 在未完成正式流程前直接改變升級層級 |
| 升級中 | 表示企業升級正在正式處理 | 玩家在營運中觸發升級流程 | 升級正式成立或失敗後離開 | 檢查升級條件、財務檢核、更新現金流 | 跳過正式檢核、提前套用升級結果 |
| 處分中 | 表示企業正在進行正式處分 | 玩家決定處分企業且進入正式交易流程 | 處分正式成立或失敗後離開 | 處分檢核、貸款關聯處理、交易紀錄寫入 | 在處分完成前繼續套用企業收益 |
| 已處分 | 表示企業不再由玩家持有 | 企業正式處分完成 | 新的正式收購成立後離開 | 保留正式歷史紀錄、等待再次收購 | 再次升級、再次結算現金流 |

# Rules

## 企業正式責任規則

- 企業屬於正式資產主體之一。
- 企業只能依正式收購流程取得，不得以非正式名稱或同步副本取代。
- 企業正式結果必須可追溯到資產系統、財務系統、貸款系統或市場系統的正式來源。
- 企業的正式狀態不得由卡片顯示、暫存結果或其他非正式副本決定。

## 收購規則

- 企業收購屬於正式交易，必須先通過財務檢核，才可正式成立。
- 若企業收購來源來自正式市場或正式卡片，必須先完成對應上游揭示與生效流程，才可進入收購。
- 收購完成後，企業所有權必須同步由資產系統承接。
- 收購完成後，企業交易紀錄必須完整寫入。
- 收購完成前，不得視為已取得企業現金流或其他企業效果。

## 升級規則

- 企業升級只能在企業處於營運中時進行。
- 企業升級屬於正式變更，必須先通過財務檢核，才可正式成立。
- 企業升級完成前，不得提前套用升級後的現金流或其他正式效果。
- 企業升級完成後，必須同步更新企業現金流、升級層級與正式交易紀錄。
- 若企業升級會影響企業貸款或其他附掛負債，必須交由貸款系統承接正式處理。

## 現金流規則

- 企業現金流屬於正式財務來源之一。
- 企業現金流必須在月結算中納入財務系統的正式計算。
- 企業現金流的變動來源，必須能對應企業收購、企業升級、企業市場更新或正式卡片 / 正式事件結果。
- 企業現金流不得在未正式成立前提前計入月結算。
- 企業現金流若需要調整，必須留下可追溯的正式來源。

## 企業貸款規則

- 企業貸款屬於正式負債，且只可與企業建立正式附掛關係。
- 企業貸款的成立、還款與清償，必須由貸款系統與財務系統的正式規則承接。
- 企業貸款不得以一般企業現金流的名義自動消失。
- 企業處分時，若存在企業貸款，必須先完成對應的正式關聯處理。
- 企業貸款不等於強制負債，兩者不得混為同一正式規則。

## 企業市場規則

- 企業市場的正式價格與生效狀態必須由市場系統承接。
- 本文件只承接企業市場對收購、升級、處分與估值的正式影響，不重複定義行情更新流程。
- 企業市場標的若尚未正式生效，不得作為正式收購或正式估值依據。
- 企業市場價格不得直接改變企業所有權。
- 企業市場的正式結果若由卡片或正式事件觸發，必須先完成上游揭示與結算。

## 與其他系統的交界規則

- 企業所有權由資產系統承接，本文件不得自行另建第二份所有權權威。
- 企業交易成立由財務系統承接，本文件不得直接讓交易跳過財務檢核。
- 企業貸款由貸款系統承接，本文件不得自行定義借款、還款或自動償還。
- 企業市場由市場系統承接，本文件不得自行定義行情更新或生效順序。
- 若企業效果由卡片或正式事件產生，本文件只承接企業結果，不重複定義卡片或事件生命週期。

# Flow

```text
開始
  ->
企業市場標的或正式企業來源成立
  ->
確認是否要收購
  ->
是
  ->
進入正式財務檢核
  ->
通過
  ->
正式收購成立
  ->
更新所有權、貸款關聯與交易紀錄
  ->
進入營運中
  ->
若觸發升級
  ->
確認升級條件
  ->
進入正式財務檢核
  ->
通過
  ->
正式升級成立
  ->
更新現金流與正式紀錄
  ->
回到營運中
  ->
若進入處分
  ->
處理貸款與附掛關聯
  ->
正式處分成立
  ->
進入已處分
  ->
完成
```

```text
開始
  ->
到達月結算點
  ->
取得企業正式現金流
  ->
交由財務系統納入月結算
  ->
更新正式財務摘要
  ->
完成
```

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待收購 | 進入收購中 | 玩家提出正式收購 | 待收購 -> 收購中 | 待收購 -> 營運中、待收購 -> 升級中 |
| 收購中 | 進入營運中 | 收購通過財務檢核且正式成立 | 收購中 -> 營運中 | 收購中 -> 升級中 |
| 收購中 | 回到待收購 | 收購流程失敗或取消 | 收購中 -> 待收購 | 收購中 -> 升級中 |
| 營運中 | 進入升級中 | 玩家觸發正式升級 | 營運中 -> 升級中 | 營運中 -> 待收購 |
| 營運中 | 進入處分中 | 玩家觸發正式處分 | 營運中 -> 處分中 | 營運中 -> 收購中 |
| 升級中 | 回到營運中 | 升級正式成立 | 升級中 -> 營運中 | 升級中 -> 待收購 |
| 升級中 | 回到營運中 | 升級流程失敗或取消 | 升級中 -> 營運中 | 升級中 -> 待收購 |
| 處分中 | 進入已處分 | 處分正式成立 | 處分中 -> 已處分 | 處分中 -> 升級中 |
| 已處分 | 進入收購中 | 新的正式收購成立 | 已處分 -> 收購中 | 已處分 -> 營運中、已處分 -> 升級中 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 企業來源來自正式市場，但市場尚未生效 | 是否可直接收購或估值 | 不可。必須先由市場系統完成正式生效，才可作為收購或估值依據。 |
| 企業來源來自正式卡片或正式事件，但卡片尚未揭示 | 是否可直接處理企業效果 | 不可。必須先完成卡片或事件的正式揭示與結算。 |
| 企業正在升級時又觸發月結算 | 升級後現金流是否可提前採用 | 不可。升級完成前仍以升級前正式狀態計算。 |
| 企業處分時仍存在企業貸款 | 是否可直接完成處分 | 不可。必須先完成對應貸款與附掛關聯的正式處理。 |
| 企業已處分後又嘗試套用現金流 | 已不持有的企業是否仍有正式效果 | 不可。已處分企業不得再產生企業現金流或升級效果。 |
| 企業收購與其他正式交易同時發生 | 是否可任意合併 | 不可。每一筆正式交易都必須依各自的財務檢核與正式紀錄完成。 |
| 遊戲已正式結束 | 是否可再建立企業收購、升級或處分 | 不可。遊戲結束後不得再建立新的正式企業流程。 |

# Design Principles

- 單一職責：本文件只定義企業本體、企業收購、企業升級、企業現金流、企業貸款與企業市場承接規則。
- 模組化：資產、財務、貸款、市場與卡片生命週期分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔卡片揭示、行情更新、貸款清償或交易成立主流程責任。
- 高內聚：所有企業取得、營運、升級、處分與現金流規則集中於本文件。
- 單一權威來源：企業系統正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴資產、財務、貸款、市場與卡片系統，不得反向要求它們依賴本文件。
- 依賴方向固定：企業系統承接上游資產、財務與市場結果，不重寫其正式邊界。
- 資料與 UI 分離：本文件只描述正式企業資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程與執行細節。

# Modular Design Rules

- 本文件只負責企業系統，不承擔資產、財務、貸款、市場或卡片系統責任。
- 本文件可依賴 `docs/gdd/ASSET_SYSTEM.md`、`docs/gdd/FINANCIAL_SYSTEM.md`、`docs/gdd/LOAN_SYSTEM.md`、`docs/gdd/MARKET_SYSTEM.md`、`docs/gdd/CARD_SYSTEM.md`。
