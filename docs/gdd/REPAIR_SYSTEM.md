# Purpose

本文件定義維修廠系統的正式設計，負責說明維修廠事件、保養費、汽車判定、停回合與事件收束的正式規則與正式資料模型。

本文件不得重新定義產品規則。

所有維修廠相關正式規則皆以 `docs/spec/PRODUCT_SPECIFICATION.md` 與已確認 Decision 為正式來源。本文件僅承接上游規則，將其整理為維修廠系統的正式設計。

# Scope

## 本文件負責

- 定義維修廠系統的正式責任範圍
- 定義維修廠事件的正式邊界
- 定義汽車判定與進入條件
- 定義保養費的正式語意與財務承接
- 定義停回合的正式效果與收束條件
- 定義維修廠系統的正式 State 與狀態轉換

## 本文件不負責

- 重新定義回合順序或回合切換規則
- 重新定義棋盤移動或其他格子事件
- 重新定義財務檢核成立條件
- 重新定義資產所有權、汽車購買或汽車出售規則
- 重新定義保險理賠、貸款或其他金融服務規則
- 描述任何程式、畫面或技術實作

## 邊界原則

- 維修廠事件只負責維修廠格所觸發的正式流程。
- 汽車是否可觸發維修廠事件，由棋盤與資產的正式規則共同承接。
- 保養費屬正式財務結果，成立條件由財務系統承接。
- 停回合屬正式回合效果，完成條件由回合系統承接。
- 本文件不重複定義其他系統已明確擁有的責任。

# Definitions

| 名詞 | 定義 |
|---|---|
| 維修廠系統 | 負責管理維修廠事件、汽車判定、保養費與停回合效果的正式系統。 |
| 維修廠事件 | 玩家停留或經過維修廠格時，在符合正式汽車條件下建立的正式事件。 |
| 汽車判定 | 驗證玩家是否持有可對應正式事件的汽車資產之正式檢核。 |
| 保養費 | 因維修廠事件而產生的正式費用，必須納入財務承接與正式交易紀錄。 |
| 停回合 | 因維修廠正式結果而使玩家在後續正式回合略過擲骰與移動的效果。 |
| 事件對象汽車 | 與本次維修廠事件正式關聯的汽車資產。 |
| 維修結果 | 本次維修廠事件正式完成後所留下的費用、停回合與事件收束結果。 |
| 事件收束 | 維修廠事件已完成正式檢核、正式費用承接與正式回合效果處理後的結束狀態。 |

# State

| State 名稱 | 用途 | 進入條件 | 離開條件 | 允許操作 | 禁止操作 |
|---|---|---|---|---|---|
| 待建立 | 表示維修廠事件尚未進入正式流程 | 維修廠格正式入口成立但尚未完成汽車判定 | 汽車判定完成後離開 | 建立事件基本資料、確認事件對象汽車 | 直接套用保養費、直接套用停回合 |
| 汽車檢核中 | 表示正在確認事件對象是否為正式汽車 | 維修廠事件已成立且需要檢查汽車條件 | 汽車條件確認後離開 | 驗證是否持有正式汽車、關聯事件對象汽車 | 略過汽車判定、直接完成事件 |
| 維修處理中 | 表示維修廠事件已進入正式處理 | 汽車判定完成且事件開始處理正式結果 | 保養費與停回合效果處理完成後離開 | 套用正式維修結果、準備財務承接 | 在結果未完成前切換下一位玩家 |
| 保養費結算中 | 表示保養費正在正式成立 | 維修結果需要產生正式費用 | 財務檢核與正式交易完成後離開 | 進行財務承接、寫入正式交易紀錄 | 略過財務檢核、先行視為費用成立 |
| 停回合處理中 | 表示停回合效果正在正式寫入 | 維修結果要求玩家略過後續正式回合 | 停回合效果正式記錄完成後離開 | 寫入停回合數、交由回合系統承接 | 在正式記錄前直接跳過回合 |
| 已完成 | 表示維修廠事件已正式收束 | 汽車判定、保養費與停回合效果皆已完成 | 無 | 交還回合流程、保留正式結果 | 再次套用同一事件效果 |

# Rules

## 維修廠事件規則

- 玩家停留或經過維修廠格時，只有在持有汽車的情況下，才可建立維修廠事件。
- 維修廠事件屬正式事件，必須遵守事件系統的完成與阻塞模型。
- 維修廠事件完成前，不得切換下一位玩家。
- 維修廠事件一旦成立，即不得以未完成狀態直接跳過正式收束。
- 經過維修廠與停留維修廠都必須先擲一次正式事件骰點。

## 汽車判定規則

- 維修廠事件必須先完成汽車判定，才可進入正式處理。
- 汽車判定的正式來源以資產系統所承認的汽車持有狀態為準。
- 若玩家未持有可對應的正式汽車，則不得建立維修廠事件。
- 汽車判定完成前，保養費與停回合效果不得正式成立。

## 保養費規則

- 保養費屬正式財務結果，必須依財務系統完成正式承接。
- 保養費成立前，必須完成正式財務檢核。
- 保養費完成後，必須留下正式交易紀錄。
- 保養費是否成立，不得以畫面顯示或暫存狀態代替正式結果。
- 保養費金額固定為維修事件骰點結果乘以 `2,000`。

## 停回合規則

- 維修廠事件可產生停回合效果。
- 停回合效果屬正式回合規則，必須由回合系統承接。
- 停回合只對後續正式回合生效，不得提前略過尚未完成的正式事件。
- 停回合效果正式寫入後，玩家後續回合才可依正式規則略過擲骰與移動。
- 只有停留維修廠時才會產生一次停回合效果；經過維修廠不產生停回合。

## 完成規則

- 維修廠事件完成，必須以汽車判定、保養費承接與停回合處理都已完成為準。
- 若維修廠事件有正式財務結果，必須先完成財務承接，事件才可收束。
- 若維修廠事件產生停回合效果，必須完成正式記錄後，事件才可收束。
- 維修廠事件完成前，不得視為當次回合已結束。

## 交界規則

- 維修廠事件的建立與完成，必須服從事件系統的正式模型。
- 維修廠格的經過與停留入口，必須服從棋盤系統的正式判定。
- 與汽車持有相關的正式條件，必須服從資產系統。
- 與保養費相關的正式交易，必須服從財務系統。
- 與停回合相關的正式效果，必須服從回合系統。

# Flow

```text
開始
  ->
維修廠格正式入口成立
  ->
確認玩家是否持有汽車
  ->
否
  ->
不建立維修廠事件
  ->
完成

開始
  ->
維修廠格正式入口成立
  ->
確認玩家是否持有汽車
  ->
是
  ->
建立維修廠事件
  ->
進入汽車檢核中
  ->
進入維修處理中
  ->
擲一次維修事件骰
  ->
若產生保養費，進入保養費結算中
  ->
若產生停回合，進入停回合處理中
  ->
完成正式承接
  ->
維修廠事件已完成
```

# State Machine

| State | Transition | Trigger | Allowed Transition | Forbidden Transition |
|---|---|---|---|---|
| 待建立 | 進入汽車檢核中 | 維修廠正式入口成立且玩家持有汽車 | 待建立 -> 汽車檢核中 | 待建立 -> 已完成 |
| 汽車檢核中 | 進入維修處理中 | 汽車條件已正式確認 | 汽車檢核中 -> 維修處理中 | 汽車檢核中 -> 已完成 |
| 維修處理中 | 進入保養費結算中 | 事件需要正式承接保養費 | 維修處理中 -> 保養費結算中 | 維修處理中 -> 已完成 |
| 維修處理中 | 進入停回合處理中 | 事件需要正式承接停回合 | 維修處理中 -> 停回合處理中 | 維修處理中 -> 已完成 |
| 保養費結算中 | 進入停回合處理中 | 保養費正式承接完成，且仍需處理停回合 | 保養費結算中 -> 停回合處理中 | 保養費結算中 -> 待建立 |
| 保養費結算中 | 進入已完成 | 保養費正式承接完成且無停回合效果 | 保養費結算中 -> 已完成 | 保養費結算中 -> 待建立 |
| 停回合處理中 | 進入已完成 | 停回合正式記錄完成 | 停回合處理中 -> 已完成 | 停回合處理中 -> 待建立 |
| 維修處理中 | 進入已完成 | 無保養費與停回合待處理 | 維修處理中 -> 已完成 | 維修處理中 -> 待建立 |
| 已完成 | 無下一正式狀態 | 維修廠事件已正式收束 | 無 | 重新回到待建立、汽車檢核中 |

# Edge Cases

| 情境 | 問題 | 正式處理方式 |
|---|---|---|
| 玩家停留維修廠但未持有汽車 | 是否可建立事件 | 不可。只有持有汽車時才可建立維修廠事件。 |
| 玩家經過維修廠但未持有汽車 | 是否仍觸發正式流程 | 不可。不得建立維修廠事件。 |
| 維修廠事件成立後汽車狀態後續變動 | 事件是否失效 | 不失效。已成立的正式事件仍須依正式事件流程完成收束。 |
| 保養費成立但財務檢核未通過 | 費用是否可直接視為成立 | 不可。必須先完成正式財務檢核，未通過時不得成立。 |
| 維修結果包含停回合 | 是否可先跳過回合再處理費用 | 不可。必須先完成正式事件與正式財務承接，再由回合系統套用停回合。 |
| 同一回合內同時出現維修廠事件與其他正式事件 | 回合是否可提前結束 | 不可。必須依正式事件順序逐一完成後，回合才可結束。 |
| 維修廠事件已完成但停回合尚未正式寫入 | 事件是否可視為完全收束 | 不可。停回合屬正式結果之一，必須完成正式記錄後才可收束。 |
| 遊戲正式結束 | 是否可再建立維修廠事件 | 不可。遊戲正式結束後不得再建立新的正式事件。 |

# Design Principles

- 單一職責：本文件只定義維修廠事件、汽車判定、保養費、停回合與收束規則。
- 模組化：棋盤入口、事件生命週期、財務成立與汽車持有分別引用上游系統，不在本文件重複定義。
- 低耦合：本文件不承擔回合切換、汽車購買、保險理賠或交易成立主流程責任。
- 高內聚：所有維修廠進入、骰點、保養費與停回合規則集中於本文件。
- 單一權威來源：維修廠系統正式規則以上游 Product Specification 與 Confirmed Decision 為準。
- 不可循環依賴：本文件只能依賴回合、事件、棋盤、財務與資產系統，不得反向要求它們依賴本文件。
- 依賴方向固定：維修廠系統承接上游入口與生命週期，並把費用與停回合結果交由上游系統承接。
- 資料與 UI 分離：本文件只描述正式維修廠資料與規則，不描述畫面與操作元件。
- 規則與實作分離：本文件不描述技術流程與執行細節。
- 產品規則不得寫進程式：維修廠規則調整必須先更新正式規格。

# Writing Rules
